# 存量项目接入指南（附带技能文件 · 已开工项目专用）

> **本文件是什么**：一份独立附带的引导文件，服务「已经开始工作一段时间、但尚未建立项目管理结构」的存量项目。
> **它与主技能的关系**：独立存在，不写入主技能协议正文，**不在接手路径上**——只有存量项目接入那一次需要读它。
> **谁读它**：已开工项目的 AI 或项目管理者——单独读取本文件，理解项目管理方式、创建管理结构、轻量登记当前信息，然后按主技能正常管理。

---

## 一、适用场景

项目已有实际工作成果（代码 / 文档 / 多轮对话历史），但存在以下缺失：

| 缺失项 | 表现 |
|---|---|
| 无技能总表 | 没有 SKILL.md，AI 不知道管理协议 |
| 无目录总表 | 没有 MAP.md，AI 不认路 |
| 无工作任务流程 | 没有 tasks/，AI 不知道做什么、谁在做 |
| 无工作记录 | 没有 reports/ / INDEX.md，历史无法追溯 |

此时 AI 读取本文件，执行「接入流程」，把项目纳入项目管理体系。

---

## 二、创建是通用第一步，存量项目只多「轻量登记」

| 环节 | 正常项目（一开工就用本技能） | 存量项目（半途接入本技能） |
|---|---|---|
| 读取技能 | 初始化时读一次 | 接入时读一次 |
| 创建管理区 | **同样需要创建**（开工信息就在手边） | **同样需要创建**（创建为主） |
| 历史整理 | 无需（无历史） | **轻量登记**：只登记当前会话可见的关键信息，**不做深度整理分析** |

> **关键点**：
> 1. **创建是通用第一步**：任何项目接入本技能，都是先创建管理区（MAP / STATE / tasks/ / reports/ / INDEX），之后才是对整个项目的管理——不存在"直接读取"的起点。
> 2. **存量项目不做深度整理**：深度思考分析历史是巨大工程（项目越深越恐怖）——所以接入时**只轻量登记**（当前会话直接可见的信息），不做历史深挖。
> 3. **历史靠渐进整理**：不一次性整理，在后续工作中边做边归类（见「渐进整理机制」），历史缺口按需回溯补录。
> 4. **技能不重复读取**：创建完成后，AI 只按创建出的工作文件（任务卡 / MAP / reports）运行，不需要再次读取技能本身。

---

## 三、执行流程（先查重 + 五步：轻登记 → 建结构 → 回填 → 首记录 → 运行）

### 第〇步：先查重——本项目管理区是否已存在（必做）

接入开始前先探测 `{MGMT_ROOT}`（及技能源包可见范围）下**是否已有该项目的管理区/工作区**：
- 已有 → **先归并或确认唯一正本**（沿用该正本继续管理；历史缺口按既有协议渐进整理），**禁止另起新管理区**——同项目双管理区会造成状态分裂（读取代价与出错率上升）；
- 没有 → 继续正常接入。

> 触发点：无论新项目初始化还是存量接入，复制模板/建目录之前都先做本步。

### 第一步：轻量登记当前信息（不做深度整理）

只登记**当前会话直接可见**的关键信息，形成「初始信息清单」：

- **项目是什么**：一句话定位 + 技术栈 + 工程路径 + 不涉及的边界
- **当前进行中的工作**：正在做/未完成的（这是任务卡的素材）
- **待确认的决策点**：会话中悬而未决的问题、等待用户拍板的事项
- **已知限制/问题**：BUG、环境限制、遗留风险
- **关键里程碑**（可选）：有据可查的重大改动，一句话即可

> **不做深度整理**：不追挖历史细节、不做全量分析——深度思考是巨大工程，留给「渐进整理机制」按需补录。历史中无法还原的部分标注「待按需整理」，不强迫一次性完成。

### 第二步：建立项目管理区结构

按主技能规范在工作区创建——**文件组成以 `references/artifacts.md` §1「管理区文件清单」为唯一清单**（新项目初始化与存量接入共用同一份，不产生两套组成）：实例化 MAP / STATE / INDEX / REVIEWS 模板；原样复制 SKILL.md、MANIFEST.md、`references/`、`scripts/`、archives/README.md、tools/README.md；实例化 `config/defaults.yml` → `config.yml`；创建 tasks/、reports/、archives/done/ 空目录。

### 第三步：回填初始状态（轻量，只填当前可见信息）

| 文件 | 回填内容 |
|---|---|
| `SKILL.md` + `references/` | 原样复制协议入口与正文（逐字副本）——MAP「协议正文」引用即指向此 |
| `MAP.md` | 环境/规则/协议/路径注册表（固定四段；环境段含 [技能源包路径]、[备份方式]、[裁决者] 占位符，规则段确认 INDEX 行数 / reports 归档阈值 / AI 定期排查开关三项配置） |
| `STATE.md` | 写入「初始信息清单」的现状摘要（人读区 + AI 区） |
| `REVIEWS.md` | 复制 REVIEWS.template.md 实例化（元管理记录落点——技能复盘/恢复登记写此，不进 reports/INDEX） |
| `INDEX.md` | 只建少量关键 `[完成]` 行（有据可查的里程碑）；其余历史不建，待渐进整理 |
| `tasks/` | 为**当前进行中的工作**建任务卡（描述 + 要点 + 涉及 + 承接），悬而未决的决策点写入任务卡要点 |
| `tools/README.md` | 复制技能源包工具区入口（总说明 + 防御规则 + 细分规范表）；子规范（visualize/schedule/report）用时再从技能源包拉取 |

### 第四步：创建首条记录（接入锚点）

在 `reports/` 写一条**接入记录**：

```
# 接入记录 YYYY-MM-DD
- 事件：本项目通过「存量项目接入指南」纳入项目管理
- 来源：历史信息来自会话汇总（截至 YYYY-MM-DD），非逐条工作记录
- 已知缺口：历史中无法完整还原的部分（如 [xxx]），标注待补充
- 此后：按主技能协议运行（任务卡驱动 / 提交分派 / 原地更新）
```

同时在该记录对应 `INDEX.md` 行标记类型 `[接力]`（作为新管理周期的起点）。

### 第五步：进入正常运行（创建完成，不再读技能）

- 至此管理文件已**创建完成**，项目进入正常运行：读任务卡 → 作业 → 提交分派、原地更新、摘要写回
- **不再重复读取技能**（SKILL.md / 本文件）：AI 只按创建出的工作文件（任务卡 / MAP / reports）运行
- 历史缺口在 STATE 标注「待补充」，需要时向用户确认补齐
- 本文件使命完成（除非新项目再次需要接入）

## 四、渐进整理机制（边工作边归类 · 历史按需补录）

**不做一次性深度整理**，通过以下方式让项目逐步规范：

1. **新工作即规范**：从接入日起，每次提交自动归类——写交接/总结（reports/）→ 更新 INDEX（[接力]/[完成]/[废弃]）→ 原地更新 STATE → 更新任务卡。新产生的信息从第一天起就规范化。
2. **历史按需补录**：某段历史需要追溯/审视时，再按需整理并补录进 INDEX / STATE——一次只补一段，不一次性全补，避免深度思考的巨大成本。
3. **关键教训渐进沉淀**：工作中发现的历史决策、约束、教训，随手补录进任务卡要点或 STATE，积少成多。
4. **归档自然发生**：reports 篇数达到 MAP 规则段「reports 归档阈值」（默认 20）时按既有规则滚动归档，旧历史随之纳入规范管理。

> **效果**：接入成本低（不因深度整理而恐怖），后续每一天都在渐进整理——项目越跑越规范，且整理成本分散在日常工作中。

## 五、边界与注意事项

1. **不编造历史**：只登记会话中有据可查的信息；无据的标「待按需整理」
2. **不混入主技能**：本文件独立分发，不修改 SKILL.md / README / 蓝图 / 模板；主技能必读流程不变
3. **一次接入**：接入完成后按主技能运行，本文件只用于「存量项目首次接入」
4. **决策点接住**：当前会话中待用户确认的问题，必须在接入时汇入 STATE 决策点或任务卡要点——接入即接住，不遗漏
5. **可信度标注**：会话登记的历史标注「来自会话汇总（未逐条核验）」，正式工作记录标注「正式记录」，两者在 INDEX 中可区分
6. **不强迫一次性整理**：历史缺口长期存在是允许的（标「待按需整理」）；需要该段历史时才补录，不以整理完整为接入前提
7. **[强制] 存量接入首轮不得启用阻断**（防「用新噪声替换旧噪声」）：
   ① **只读盘查**（`overview.py` / `code_metrics.py <源码根>` / `correctness_rules.py <源码根>`，并**报扫描范围**）；
   ② **抽样精度抽检**（样本量 / 真阳性 / 假阳性 —— `references/code-quality.md` §10 [强制]）；
   ③ **假阳高的规则降为 `[建议]` 或人检**；
   ④ **基线冻结为豁免**（`# noqa: … reason=<理由> sha256=<指纹>` + 回查周期）而不是当场打回；
   ⑤ **此后只对新改动启用阻断**（老代码松、新代码严）。
   > 依据：`code-quality.md` §1.4（范围不达标时「退出码 0」只是**没看**）· §10（**未抽检的规则误报 9/9**）· §3 分层宽松度 · §2 豁免机制 · `…schema.md` §6 四档（允许 GRAY/YELLOW）。
