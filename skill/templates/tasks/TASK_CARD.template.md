> **更新**：未完成 → **必须建卡**（包括尚未建卡、只在当前对话里的工作）；人读区由 AI 区**机械派生**——任务行←描述首句、状态行←状态字段、下一步←要点①（无要点填「—」），更新时同步重写；完成 → 写总结后**归档任务卡**到 `archives/done/`（**不删卡**，保留完成记录）。
> **进度锚点写法（断点续传）**：工作中**检查点写回**——每完成一个子步骤 / 一次验证通过，就改写本行（单行覆盖，只写自己认领的卡，无并发冲突）；断网 / 断电 / 断 token 等中断来不及提交时，卡上自然留下最新落点，下一位沿锚点 + 实际文件状态（`git status`）续作；正常提交时锚点内容已被要点/交接吸收 → 清「—」，**交接格式零变化**；任务取消直接归档的卡，锚点保留原样（可追溯的中断记录）。
> **字段质量门槛**：要点=可执行动作（做什么+在哪文件，禁止"继续优化"类空话）；涉及=具体文件路径（禁止"相关文件"）；代码根路径=绝对路径（冷启动凭此定位，不必先读 MAP）；上次交接=裸路径（多条用逗号分隔）；加括注/反引号/说明文字会导致指针校验误报，**只填单个裸路径**（加括注/反引号/说明文字会导致指针校验误报）；已提炼=读过的 reports 必须把增量写回要点，否则下一位要重读同一篇。
> **提交协议速记**：先生成 EVENT-ID 并写 reports → 更新本卡 → 先追加冷区 `archives/INDEX_archived.md` 再 CAS 更新 INDEX → STATE 字段级更新；提交门禁任何一项失败都**阻塞完成**；设计卡只有定稿后才能生成本卡；档案只能按归档算法移动。
