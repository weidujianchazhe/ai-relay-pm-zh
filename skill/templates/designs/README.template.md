# 设计资产研究验证区 · 路由表（`designs/`）

> **本表是设计区的唯一入口。** 主技能（`SKILL.md`）与管理区**只路由到本表**，
> **不逐项登记设计区内的文件** —— 设计区多一份文件，管理区**不需要**知道。
> **原则**：★ **管理区 → 工程区 = 完整路由**；**管理区 → 设计区 = 只到本表**（资产定位 ≠ 工作管理）。

## 地图（本区长什么样）

```
designs/                          ← 设计资产研究验证区（仍在管理区内）
├── README.md                     ← ★ 本表（设计区唯一入口）
├── SKELETON.html / SKELETON.md   ← 项目当前工程模型（结构 → DESIGN-ID 可追溯）
├── <设计卡名>.md                  ← ① 设计卡·详述（为什么这样设计）
├── <设计卡名>.blueprint.html      ← ① 设计卡·蓝图（给人看方向）
├── _assets/                      ← ② 设计过程资产（概念稿 / 设计稿 / 参考图）
├── _research/                    ← ③④ 研究资料 + 研究验证脚本
└── archives/                     ← 已归档的设计卡（详述 + 蓝图成对移入）
```

> ★ **`_assets/` 与 `_research/` 只在真有东西时才建**（不预先建空目录 —— 空目录会被判为残留）。
> ★ **子目录需要时再各自加 README**（如 `_research/README.md` 列该主题的文件）；**默认只维护本表**。
## 本区住什么（四类）

| 类 | 放这里 | 不是这里 |
|---|---|---|
| **① 设计卡** | `<卡名>.md`（详述）+ `<卡名>.blueprint.html`（蓝图）；**有 `DESIGN-ID`** | — |
| **② 设计过程资产** | `_assets/`：概念稿 / 设计稿 / 参考图（**不会被引擎引用、不会被打包**）| **最终美术 / 3D / 音频素材** ⇒ 工程区 |
| **③ 研究资料** | `_research/`：缺口分析 / 对照实验 / 阶段报告 | — |
| **④ 研究验证脚本** | `_research/<主题>/`：验证**某个假设成不成立** | **工程验证脚本**（验证正式实现合不合格）⇒ 工程区 |

> ★ **判据一句话**：**它会不会被【打包】或被【引擎/代码引用】？** 会 ⇒ 工程区；不会 ⇒ 本区。

## 骨架（不放本表）

`SKELETON.html` / `SKELETON.md` —— **项目当前工程模型**（总体架构 / 模块关系 / 数据与调用主路径 / 结构 ↔ `DESIGN-ID`）。
> 它是**模型**，不是本表；本表只回答「**该读哪个文件**」。

## 归档

`archives/` —— 走完流程的设计卡（详述 + 蓝图一起移，**不删除**）。见 `references/design.md` §4。

## 在设计阶段里区分：设计 / 研究 / 验证（★ 只在本协议内定，不进主管理协议）

> **入口只到「要不要进设计阶段」这道门。** 进了设计阶段，才用本节区分；**主技能不承载本节内容**。

| 判据（看产出改变了什么）| 类别 | 产出形态 | 有 `DESIGN-ID`？ |
|---|---|---|---|
| 改变「**系统应该是什么**」| **设计** | 设计卡（详述 + 蓝图）| ★ **有** |
| 只回答「**现状是什么 / 行不行 / 能不能**」| **研究** | 报告 / 对照实验 / 缺口分析 | ★ **没有** |
| 只提供「**凭什么信**」的证据 | **验证** | 脚本 + 结果数据 + 证据 | ★ **没有** |

> ★ **设计 vs 其余**是**机检**的：`designs/` 根下**有 `DESIGN-ID`** = 设计卡，**没有** = 过程资产（`validate_workspace` 已按此分界）。
> ★ **研究 vs 验证**是**语义**的：只需本表判据，**不设机检**（避免字符串判据误报）。
> ★ **收敛方向**：**研究 / 验证 → 设计 → 工程**。研究/验证**不产生 `DESIGN-ID`**；结论成立后另建**设计卡**，并回填任务卡的 `DESIGN-ID`。

## 在工程区做研究/验证时，怎么归（★ 产出与工具分开）

| 对象 | 归哪里 | 说明 |
|---|---|---|
| **产出**（报告 / 结论 / 对照数据 / 截图证据）| ★ **`_research/<主题>/`** | 不会被引擎引用，但它是**论证依据** |
| **工具·只服务研究** | ★ **`_research/<主题>/`** | — |
| **工具·也会被工程用**（回归 / 构建 / 接口检查）| ★ **留工程区**，`_research/<主题>/README.md` 留**一行指针** | ★ **指针，不是拷贝**（拷一份必然过期）|
| **原创设计稿 / 概念图** | ★ **`_assets/`** | — |
| **工程里截的图 / 导出的模型** | ★ **留工程区**，`_assets/` 只放**指针** | 与工程版本绑定，重生成即覆盖 |

> **谁判 / 何时判**：**执行 AI**，在写 6+1 的「**本次涉及工程信息**」块时判（那块强制列出本次动了哪些路径）。
> **判不准**：按 `workflow.md` 的「**显式让渡**」记录，**不硬判、不伪装**；★ **归属取决于当前职责，可后挪**。
## 研究型任务的闭环（★ 本区最重要的一条用法）

1. **工程中发现需要研究** → 建**普通任务卡**，`DESIGN-ID` 填 **`先跳过`**（有编号、被索引追踪）；
2. **研究过程产出** → 放 `_research/`（报告 / 数据 / 验证脚本）；
3. **研究出结论** → 建**设计卡** → 把任务卡的 `DESIGN-ID` 从 `先跳过` 改成真实 `DSN-…`（**单向、可追溯**）；
4. **设计定稿** → 拆后续任务卡；`_research/` 里的材料**留档**（作为设计依据的证据，不删）。

> ★ **`先跳过` 不是「不做设计」，是「设计依据还没到位」。**

## 本区检查（结果进管理区，不进本区）

本区**不存记录**：检查结果写管理区的 `REVIEWS.md`，资产仍只在本区。

```
python scripts/closeout.py <管理区> designs-check
```

查五条（**只查结构，不查内容**）：
1. 设计卡 `<卡>.md` 与 `<卡>.blueprint.html` 成对
2. `_research/<主题>/` 每个主题有 README
3. `_assets/` 每个文件首 3 行内有「来源」
4. 无 `.tmp` 残留、无非协议空目录（`archives` / `_research` / `_assets` 可空）
5. `archives/` 详述与蓝图成对

★ **本区不在 `validate_workspace` 范围**；也不进管理区的卡 / 索引 / 归档。
