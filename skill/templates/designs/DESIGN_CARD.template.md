- **DESIGN-ID**：`DSN-YYYYMMDD-XXXXXX`（创建后不可变）
- **状态**：草案 / 评审中 / 已定稿 / 已拒绝 / 已废弃
- **提议人**：[AI 标识（`scripts/stamp.py --ai-id` 产生）]
- **定稿人**：[管理者；未定稿填「—」]
- **定稿 EVENT-ID**：`EVT-...`；未定稿填「—」
- **影响模式**：light / standard / coordination
- **范围与不变式**：[目标、非目标、必须保持的协议约束]
- **角色/权限变化**：[新增 owner、审计或裁决责任]
- **迁移与回滚**：[文件集、兼容策略、失败处理]
- **验证证据**：[检查 / fixture / 命令及结果]
- **拆分出的任务卡**：[拆出的 TASK-ID 列表，逗号分隔；**未拆完填「—」**——本字段是归档门禁判据]

> **配套蓝图**：同目录下必须存在 `<主题>.blueprint.md`（结构视图，给人看）。
> **归档**：全部拆完（或作废）后跑 `closeout.py <管理区> design-archive "<主题>"`，两份文件一起移入 `designs/archives/`。
> **修订单价**：蓝图每轮整篇重写（短）；详述只做定点修改，改一处补一行 `> 修订：<理由>`。详见 `references/design.md`。

## 生命周期门禁

1. 草案 → 评审中：补齐范围、权限、迁移和验证证据。
2. 评审中 → 已定稿/已拒绝：管理者写定稿或拒绝 EVENT-ID；**未定稿不得生成任务卡**。
3. 已定稿 → 任务卡：每张任务卡必须填写本 DESIGN-ID，并生成新的 TASK-ID。
4. 已定稿 → 已废弃：管理者写废弃 EVENT-ID；已生成的任务卡不回写历史，只按新决策处理。
