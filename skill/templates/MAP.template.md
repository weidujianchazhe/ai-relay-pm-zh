## 三、协议速记（高频规则就地可读；权威源为 `references/`）

> 以下 8 行为高频速记，覆盖一次常规提交的全部动作；细则见 `references/` 下对应文件。
> **本节是"速查表"，不是"派生视图"**——它由人工维护，与细则不一致时**以 `references/` 为准**。
> 保留它的理由见 `references/change-control.md` §0「速查表 ↔ 细则」：高频规则必须就地可读，指针只兜低频细节。

1. **任务卡驱动**：接手先读对应任务卡（`tasks/`），开工前在卡「承接」认领，不漫读全项目
2. **提交分派（closeout routing）**：未完成 → 必须建卡；有下一步 → 完整交接 + 原地更新任务卡；无下一步 → 简化总结 + 归档任务卡到 `archives/done/`（**不删卡**）；提交门禁失败 → 阻塞完成
3. **提交流程（closeout checklist）**：交接 reports → 卡更新/归档 → INDEX 加一行（先写不可变冷区、再 CAS 更新热区；行永不丢失）→ STATE 字段级更新（禁止整文件盲覆盖）
4. **最小交接**：6 块 + 第 7 块「任务卡更新」（有对应任务卡时必填）；不写 diff、不复制代码
5. **命名规范**：记录 `YYYY-MM-DD_主题_AI标识.md`（AI 标识 `{平台}-{机器码}[@{角色槽}]`，由 `scripts/stamp.py --ai-id` 产生；写前先 list 目录确认无同名）；任务卡按工作命名
6. **稳定 ID 与并发**：TASK-ID / EVENT-ID / DESIGN-ID 创建后不可变；写前读 revision/hash，用原子写或 CAS，写后验；单写者冲突写 `CONFLICT_*.md` 交管理者，**不以时间戳裁决**
7. **摘要写回（write-back）+ 进度锚点**：读 reports 后把增量摘要写回卡（**每篇记录最多被读一次**）；工作中检查点写回卡「进度锚点」行，中断沿锚点 + `git status` 续作，提交沉淀后清「—」
8. **档案与元数据通道**：`reports/` 与 `archives/` 禁删禁移（唯一例外=归档流程，移后同步 INDEX 行指向）；新增文件/路径/分支登记 MAP；技能自身事务写 `REVIEWS.md`，不写 `reports/`、不登 INDEX
