# 产物规范（Artifacts）

> **何时读**：写任务卡 / 写交接记录 / 改字段 / 建索引行时。
> **本文档是「冻结区」的所在地**——下面所有名字都是脚本的**功能接口**，改名即破坏功能。
> **先读 §9**：外部记忆的五个分区、一次循环的出入、以及「本包只管路径不管能力」的权限边界。

---

## 0. 两种形态：卡片模式与工作区模式

**不是所有项目都要建工作区。** 判定见 `references/onboarding.md` §1；此处只记产物差异。

| | 卡片模式（`card`） | 工作区模式（`light` / `standard` / `coordination`） |
|---|---|---|
| 产物 | **一个卡片文件**（模板 `templates/CARD.md`） | 见 §1 管理区文件清单 |
| 位置 | 任意（项目根亦可） | `{MGMT_ROOT}/<项目名>/` |
| 交接载体 | 卡片内的「交接流水」（**追加式**） | `reports/` 记录 + 索引指针链 |
| 遍历方式 | 人读卡 | 指针链（卡「上次交接」→ 记录「下一步」→ 索引 [接力] 行） |
| 门禁 | 无 | `scripts/` 全套 |
| 升级 | 卡片内容原样迁入任务卡，再按 §1 建工作区 | — |

> **卡片模式不做**（是定义，不是缺陷）：无索引、无快照、无并发控制、无归档、无门禁。
> **升档信号**：出现第二个写者 / 流水超过约一屏 / 需要「谁在做什么」的全局视图。

## 1. 管理区文件清单

```
{MGMT_ROOT}/<项目名>/
├── SKILL.md              协议入口（路由表；随工作区走）
├── MANIFEST.md           版本与文件清单声明（单一权威源）
├── references/           协议正文逐字副本（随工作区走，**不在接手路径上**）
├── scripts/              随包脚本副本（工作区可自跑门禁，不依赖源包在不在）
│   └── local/            项目自定义脚本（**技能包升级不覆盖**；见 scripts/local/README.md）
├── config.yml            本工作区的运行时配置（由技能包 config/defaults.yml 实例化而来）
├── MAP.md                项目地图：环境 / 规则 / 协议摘要 / 路径注册表（低频写）
├── STATE.md              当前快照：人读区 + AI 区（字段级更新）
├── REVIEWS.md            元数据通道：复盘 / 版本 / 恢复登记（追加式）
├── tasks/                任务卡（每卡一文件，按工作命名）
├── reports/              交接记录 / 简化总结（每次一篇）
├── INDEX.md              索引热区（最近若干行）
├── examples/             范例库（**按需**；从技能包 examples/ 复制骨架后自行积累；规则见 references/code-style.md §S5）
├── designs/              设计区（**不在接手路径上**；形态与归档规则见 references/design.md）
│   ├── <主题>.md           详述（叙述：范围 / 迁移 / 验证 / 理由）
│   ├── <主题>.blueprint.md 蓝图（结构：一屏可扫，给人看）
│   └── archives/           设计归档（已拆完全部任务 / 已作废）
├── archives/
│   ├── done/             完成卡归档
│   └── INDEX_archived.md 索引冷区（不可变全量）
└── tools/                可选工具区（按需拉动，不进接手路径）
```

## 2. 冻结区（**改名即破坏功能**）

| 类别 | 冻结值 | 消费者 |
|---|---|---|
| **任务卡字段** | 「承接」「进度锚点」「上次交接」「已提炼」「代码根路径」「涉及」「设计偏离」「派发摘录」「验收状态」 | 指针校验 / 断链修复 / 提交门禁 |
| **任务卡字段分层（③ 已确立）** | ① **Required**（`REQUIRED_CARD_FIELDS`，6 个，逐卡必须存在 ✓）② **Skeleton**（`CARD_SKELETON_FIELDS`，建卡时提供的标准字段，**可继续扩展** ✓）③ **Extension**（项目/任务自身的关联信息——**不是代码实体** ✗，只是「不违反核心契约即允许存在额外结构化字段」✓）。解析器本就宽容（未知字段不报错 ✓）；**不设 `OPTIONAL_FIELDS` 白名单** ✗ | 已建立 |
| **交接 6+1 块名** | 「本次需求」「本次涉及工程信息」「改动点」「验证结果」「数据影响」「下一步」「任务卡更新」 | 提交流程门禁的**逐块校验对象** |
| **索引列** | 「编号」「日期」「类型」「主题」「AI」「交接文件」 | 索引校验 / 指针悬空检测 |
| **类型标记** | `[接力]` `[完成]` `[废弃]` `[里程碑]` | 索引类型校验 |
| **分支码格式** | `XX0000`（两位大写字母 + 4~5 位数字） | 编号校验 / 审计 ID 锚 |
| **记录文件名** | `YYYY-MM-DD_主题_AI标识.md` | 命名校验 |
| **目录名** | `tasks/` `reports/` `archives/` `archives/done/` `designs/` `designs/archives/` `tools/` `references/` `scripts/` `scripts/local/` | 全部脚本 / MAP 路径注册表 |
| **设计区文件名** | 详述 `<主题>.md` · 蓝图 `<主题>.blueprint.md`（后缀冻结） | 成对性校验 / 设计归档脚本 |
| **设计卡字段** | 「拆分出的任务卡」 | 设计归档门禁判据 |

> **改任何一项之前**：先过 `references/change-control.md` §A 第 2 条（交叉影响检查），grep 全包列出同步清单。

## 3. 任务卡 schema

| 区块 | 内容 |
|---|---|
| **人读定位区** | 项目 / 模块 / 任务一句话 / 状态 · 下一步 —— **由 AI 区自动生成，不靠主观对齐** |
| **AI 字段区** | 编号 / 类型 / 前置定稿 / 状态 / 描述 / 要点 / 代码根路径 / 涉及 / 承接 / 进度锚点 / 上次交接 / 已提炼 / 设计偏离 / 派发摘录 / 验收状态 |

> **字段真值**以 `templates/tasks/TASK_CARD.template.md` 与 `scripts/closeout.py` 的 `CARD_SKELETON_FIELDS` 为准（`gen_views §5` 机检二者一致）；**本行只讲语义**，不逐字重复字段清单。

**字段质量门槛**：
- 要点＝**可执行动作**（做什么 + 在哪文件），禁"继续优化"类空话
- 涉及＝**具体文件路径**，禁"相关文件"
- 代码根路径＝**绝对路径**（冷启动凭此定位，不必先读 MAP）
- 上次交接＝无交接才填「—」；**填裸路径（多条用逗号分隔）**（加括注/反引号/说明文字会导致指针校验误报）
- 已提炼＝读过的记录必须把增量写回要点，否则下一位要重读同一篇
- 设计偏离＝无偏离填「—」；有偏离必写三件：**冻结决策出处 + 理由 + 回写目标**

**人读区生成规则（机械派生，不靠判断）**：
任务 ← 描述首句 · 状态 ← 状态字段 · 下一步 ← 要点①

**卡长度纪律（成本纪律，不是格式洁癖）**：单卡 ≤ `{{config:capacity.card_max_chars}}` 字符。
**卡是「定位 + 指针」，不是档案**——过程细节归 `reports/`，全局判断归 `STATE.md`，
历史归冷区。卡一长，**上手成本立刻随项目年龄增长**：实测某真实项目单卡最大 22,002 字符，
是建议上限的 7 倍，而它承载的信息本可以在记录里。超限时把内容**写回记录**，卡上只留指针与当前落点。

## 4. 交接记录 schema（最小交接 6+1）

7 个块名见 §2 冻结区。约束：

- 记录**只写本任务需要的信息**——不贴 diff、不复制代码
- 「交接 #NNN」编号置于 H1 之下第一行；编号取"当前最大值 + 1"
- 并行时段**号段分配**，撞号**让位 + 留痕**（后申报者顺延重编并写明）
- 「数据影响」块须**显式声明本轮核查过的设计文档清单**，或声明"本轮无设计级取舍、未核设计文档"——把"没查"与"查了没有"区分开

## 5. 索引 schema

| 列 | 约束 |
|---|---|
| 编号 | `XX0000` 格式；**同分支数字严格递增**；分支字母须在 MAP 分支登记中已注册 |
| 日期 | `YYYY-MM-DD` |
| 类型 | ∈ `[接力]` `[完成]` `[废弃]` `[里程碑]` |
| 主题 | 一句话摘要；**禁写裸竖线字符**（会破坏表格解析） |
| AI | 标识 `{平台}-{机器码}[@{角色槽}]`——由 `scripts/stamp.py --ai-id` 产生，见 `references/audit.md` §2.1 |
| 交接文件 | **单个裸路径**；加反引号/括号/复合值 → 指针悬空误报 |

**行序纪律**：新行按「分支 + 编号升序」插入对应位置，**不得插到表顶**（会造成同分支数值回跳）。
**不要手改**：镜像写、按序插入与溢出移行由 `scripts/closeout.py index-add` 完成（含格式/递增/重复校验与原子写）。
**移出规则**：热区满 N 行时只移出 `[完成]` / `[废弃]` 行；**`[接力]` 行留驻**直至转态（防链条节点被移出后接手断链）。

## 6. STATE schema

- **人读区**：3 行摘要（项目 / 任务分布 / 目录指引），**由 AI 区自动生成**
- **AI 区**：进行中任务条目 · 待确认决策点 · 活跃已知限制 · 并发与元数据
- **更新方式**：**字段级更新**——写前读最新，只改自己那条与人读区，**禁止整文件盲覆盖**
- **容量上限**：见 {{config:capacity.state_max_chars}}。超限时按快照纪律把历史段移入 `reports/`，只留当前快照。
- **不维护累计统计**（完成/废弃总数这类"期末余额"）—— 归索引冷区按需查询，**计数成本不随项目规模增长**

---

## 7. MAP schema

四段固定：**环境 / 规则 / 协议摘要 / 路径注册表**。
- 本文件记**结构与规则**，**永不记录进展**（进展归 STATE、记录归 reports + INDEX）
- 规则段配置项：索引热区行数 / STATE 字数上限 / reports 归档阈值 / 定期排查开关 / 协作模式
  （**没有「提交流程门禁」开关**：门禁是核心承诺，不该可关；归档与索引写入也没开关——用不用脚本由人决定）
- **路径注册表只在新增时写入**；新增文件/路径/分支必须登记
- 协议段是**速查表**（**人工维护，不是派生视图**）——高频规则就地可读；与 `references/` 不一致时**以后者为准**（见 `references/change-control.md` §0「速查表 ↔ 细则」）

## 8. 留痕类产物：只增不删，但**不是读物**

**留痕**（trace）是审计与追责的原料，与**读物**（手册、快照、卡）是两类东西。
把留痕当读物，成本会随项目年龄线性增长——**上手成本就不再有上限**，而"上手成本不随规模增长"正是本技能的承重墙。

**读取纪律（三条）**：

1. **留痕不进接手路径**。接手只有三处：任务卡 → 卡上指针指向的一篇记录 → 需要全局判断时的 `STATE.md` / `MAP.md`（见 `references/cheatsheet.md`）。
2. **留痕不整读，只定点查**。核查与恢复时按**编号 / 日期 / 关键字**取出需要的几行，而不是从头读到尾。
3. **读取面由容量上限限定**。历史不是被删掉，而是被移到冷区——**移出 ≠ 删除，冷区仍可查**。

**各留痕产物的读取面与封顶**：

| 留痕产物 | 增量 | 读取面（AI 实际会读的） | 容量上限 | 超限怎么办 |
|---|---|---|---|---|
| `REVIEWS.md` | 元数据通道：每次全盘核查追加一行机器戳；恢复动作、配置决定各追加一条 | **尾部若干行**（"最近发生了什么"） | `capacity.reviews_hot_lines`（示例默认 200 行） | 跑 `scripts/closeout.py reviews-archive` → 溢出部分**追加**到 `archives/REVIEWS_archived.md`，热区只留尾部 |
| `reports/` | 每次提交一篇 | 接手时**只读卡上指针指向的那一篇** | `capacity.report_archive_threshold`（篇数） | `closeout.py archive-reports` 滚动归档，索引指向同步 |
| `INDEX.md` 冷区（`archives/INDEX_archived.md`） | 每行一条记录 | **不整读**：按编号/日期定点取 | 不可变全量（冷区不设上限，它不被整读） | 无需处理 |
| `archives/done/` | 完工后移入的卡 | 只在"这件事以前做过吗"时按名查 | 无（每张卡是独立文件） | 无需处理 |
| `designs/archives/` | 走完流程的设计卡（详述 + 蓝图一起移） | **只按主题定点查**——"当初为什么这么定"才翻 | 活跃设计区（`designs/`）由归档保持清空 | 跑 `closeout.py design-archive`（触发条件见 `references/design.md` §4） |
| 版本控制历史（若启用） | 每次提交 | **按 commit hash 定点查** | 无 | 无需处理 |

> **为什么给 REVIEWS 封顶而不给它设"最多写几条"**：审计要求留痕**完整**（不得为了省事丢证据），
> 而阅读成本要求**有界**——两者不冲突：**写可以无限追加，读只读尾部**。
> 这正是"移出不删除"在留痕上的同一条纪律。

**归档红线在留痕上依然成立**：`reports/` 与 `archives/` 下文件**禁删禁移**（唯一例外＝归档流程，且移后必须同步索引行指向）。
`reviews-archive` 只做「先写冷区、后截热区」的追加式滚动：**任何内容都不被删除，只是换了个文件**。

## 9. 外部记忆分区与上下文循环

> 本包处理的是一个具体问题：**模型的上下文不是可靠的长期记忆**。
> 它不试图让 AI 记住更多，而是把**项目事实**放到文件系统，把上下文限制成**一次会话的工作集**。

| | 短期记忆（Context） | 外部记忆（Workspace） |
|---|---|---|
| 是什么 | 一次会话的工作集 | 项目事实的持久载体 |
| 谁管 | 宿主与 Agent 循环 | **本包**（文件 + 唯一入口 + 门禁） |
| 容量 | 有限、会被截断 | 可增长，**按需取用** |
| 失效方式 | 换窗口 / 换模型即消失 | 换人换窗口都还在 |
| 本包纪律 | **只放本次要用的** | **一切事实的落点** |

### 9.1 五个分区及其契约

| 分区 | 回答什么 | 读频 | 写频 | 容量上限 | 写入方式 |
|---|---|---|---|---|---|
| `STATE.md` 快照 | 现在是什么状态 | 高 | 低 | `capacity.state_max_chars` | 字段级更新（禁整文件盲覆盖） |
| `tasks/` 任务卡 | 做什么、做到哪 | 高 | 中 | `capacity.card_max_chars` | 承接者经唯一入口（租约保护） |
| `reports/` 记录 | 发生过什么、为什么 | 低（定点取） | 高 | `capacity.report_archive_threshold` | `closeout.py new-record` |
| `INDEX.md` + 冷区 | 全量总账（**找得到**） | 低（查） | 中 | `capacity.index_hot_rows` | `closeout.py index-add`（CAS） |
| `REVIEWS.md` 元数据通道 | 谁在何时做了什么（**证据**） | 定期 | 追加 | `capacity.reviews_hot_lines` | `stamp.py` / `lang_gates.py` / `audit_all.py` |

**读频与写频刻意相反**：读得多的写得少（稳定、可缓存），写得多的读得少（归档、定点取）。
倒过来就是典型的自伤——高频写的东西又被高频整读，成本随项目年龄线性增长。

### 9.2 一次循环的出入（取什么 / 不取什么 / 写回什么）

**取**（按形态，见 `references/onboarding.md` §4.0）：任务卡 → 卡上指针指向的那一篇记录 → 需要全局判断时的 `STATE.md`。
**不取**（在记忆里，但**不进上下文**）：全量索引、归档冷区、历史报告、`REVIEWS.md` 全文——
它们的作用是**需要时查得到**，不是**每次都要读**（读取纪律见 §8）。
**写回**（一次循环结束）：记录 → 卡 → 索引 → 快照，**一律经写入收口**——业务写走 `closeout.py`，共享文件走 `lease` 原语（两层口径见 `references/concurrency.md` §0）。

> **成本单位是字符，不是文件数。** 「读一份卡加一篇记录」说的是**读哪些**，不是**读多少**——
> 两件事分开说，才不会自我欺骗（实测上手成本见 `scripts/overview.py` 的「接手包成本」行）。

### 9.3 权限边界：本包约束的是**路径**，不是**能力**

| | 能力（能不能写） | 路径（该不该这么写） |
|---|---|---|
| 谁给的 | **运行环境**（沙箱档位 / OS 权限） | **本包**（唯一入口 + 租约 + CAS） |
| 本包能否改变 | **不能，也不试图** | 这正是本包能动的层 |
| 完全权限下 | 照旧能直接改文件 | **依然生效**：经入口的违规写会被拒绝 |

- **只走入口**：被约束——他人持有效租约、或文件已被别人改动 → **拒绝写入**（并生成冲突文件）；
- **直接改文件**：**拦不住**，但**一定留痕**——卡上记的 `NORMALIZED-SHA256` 与内容不符 → `[问题]` + 冲突文件；
- **要真正限制能力**，只能靠宿主沙箱或操作系统权限——那是**运行环境配置**，不是技能能做到的事。

> 用技能冒充权限系统，得到的是**假的安全感**；**假的安全感比没有更危险**——
> 使用者会以为「有它在就不会错」，从而不再自己核对。

**配套要求**：工作区应在 `MAP.md` 规则段**登记当前权限档位**（如 `danger-full-access` / `workspace-write` / `read-only`）。
这样「为什么有人能绕过」就有可查的解释——**登记过的取舍叫决定，没登记的叫意外**。
