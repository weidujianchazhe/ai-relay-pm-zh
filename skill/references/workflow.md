# 工作生命周期（Workflow）

> **何时读**：接手一项工作、要提交、要归档、或不确定"下一步该做什么"时。
> **数值口径**：本文件不写死数字——一律用占位符 {{config:<键>}}。查值顺序：实例 MAP 规则段 → 缺失才回落 config/defaults.yml（见 MANIFEST §数值口径）。

---

## 1. 三段生命周期

```
认领（claim）  →  作业（work）  →  提交（closeout）  →  归档（archive）
  卡「承接」       作业 + 进度锚点      提交流程             卡移入 archives/done/
```

**约定**：接手第一入口永远是 `tasks/` 里对应的任务卡——**不漫读全项目**。
开工前在卡「承接」字段认领（写入机器产出的 AI 标识），并发时这是"哪个工作单元在做什么"的唯一可见性来源。
（该标识回答「哪台机器」，不回答「哪个人」；定责见 `references/audit.md` §2.1 的边界声明。）

---

## 2. 认领（claim）

- 读对应任务卡（描述 / 要点 / 涉及 / 代码根路径）→ **够用直接开工**
- 不够 → 沿卡上「上次交接」指针读 `reports/` 上一篇 → 读后把增量**写回**卡（见 §4）
- 需要全局判断（首次接手 / 跨模块 / 整体审视）→ 读 `STATE.md` 与 `MAP.md`
- 卡「承接」已填他人标识 → **不认领**，先与用户或管理者确认 ——**仅当租约仍有效时**；租约已过期可直接 `claim`（见 `references/concurrency.md` §0）

---

## 3. 作业（work）

### 3.1 进度锚点（checkpointing）

工作中**检查点写回**写卡上「进度锚点」行——**单行、只写自己认领的卡**。

- 用途：断网 / 断电 / 断 token 等中断来不及提交时，卡上自然留下最新落点
- 下一位沿锚点 + **实际文件状态**（有 git 时看 git status）续作
- 正常提交时内容沉淀进要点/交接后**清「—」**，交接格式零变化
- 任务取消的卡锚点**保留原样归档**（可追溯）

### 3.2 写回（write-back）

读过 `reports/` 后，把增量**提炼写回**任务卡要点与「已提炼」字段。

**目的**：**每篇记录最多被读一次**。下一位接手不必重读同一篇。
**副产物**：这同时是一层**误删容灾**——读过的信息已经回到卡上。

---

## 4. 提交（closeout）

> **项数随形态变**（见 `references/collaboration.md` §1）：**light＝三项**（① 记录 ② 卡 ③ 索引），
> **standard / coordination＝四项**（多一项 ④ 快照）。**卡片模式不做提交流程**（只追加一行交接流水）。
> 脚本也随形态走，见 `references/onboarding.md` §4 的「按形态跑哪些脚本」。

### 4.1 分派规则（routing）

| 情况 | 动作 |
|---|---|
| **未完成** | **必须建卡**（包括尚未建卡、只在当前对话里的工作） |
| **有下一步** | 完整交接 + 原地更新任务卡（卡留在 `tasks/`） |
| **无下一步** | 简化总结 + **卡移入 `archives/done/`**（不删卡，保留完成记录） |

**"有下一步"的判据**：用户还要继续 / 活没做完 / 有遗留问题。
**"无下一步"的判据**：用户明确说"做完了" / 活全清。

### 4.2 提交流程（closeout checklist — **按形态三项或四项**，缺一不算提交）

```
① 交接报告   reports/YYYY-MM-DD_主题_AI标识.md（最小交接 6+1 块）
② 任务卡     原地更新，或完成后移入 archives/done/
③ 索引       热区 + 冷区镜像写，加一行
④ 快照       STATE.md 字段级更新（只改自己那条与人读区）——**standard 起才需要**
```

**顺序固定**：① → ② → ③ → ④（快照最后写，保证它反映最终状态）。

**提交时的工程验证义务**（**何时必须完成**，不是"怎么测"——规则细则归各自权威载体）：

- **每轮重构后必须运行测试验证**（流程见 `references/code-style.md` §S4）——未跑不算提交。
- **门禁基线**：单元测试与覆盖率报告是提交基线；异常注入测试（外部依赖超时、脏数据）用于核心管线。
- **界面渲染层**：以端到端（E2E）证据为准，不强制单元测试。
- 口径与阈值定义见 `references/code-quality.md` §7 与 `references/language-adapters.md` §3；**本节只规定"何时必须完成"**。

#### 分清"机械步骤"与"语义步骤"

**机械步骤一律跑脚本，不要手改共享文件**——手改两重代价：烧 token（逐字重写大文件）与写错（实测出现过整行截断、冷热计数对不上、归档后索引指向未同步）。

| 步骤 | 谁做 | 命令 |
|---|---|---|
| ① 记录骨架（块名 + 交接号自增） | **脚本**生成骨架，人填内容 | `python scripts/closeout.py <根> new-record "<主题>" --ai <标识>` |
| ② 任务卡内容（要点 / 锚点 / 已提炼） | **人**（语义） | — |
| ② 完成卡归档 | **脚本** | `python scripts/closeout.py <根> card-archive <卡名>` |
| ③ 索引镜像写 + 溢出移行 | **脚本**（冷区追加 → 热区按序插入 → 只移 [完成]/[废弃]） | `python scripts/closeout.py <根> index-add --id … --type … --topic … --record …` |
| ③ 记录滚动归档 + 索引指向同步 | **脚本** | `python scripts/closeout.py <根> archive-reports` |
| ④ 快照更新 | **人**（判断），机械部分可脚本 | — |

- **门禁失败即阻塞提交**，不得声称完成——先跑 `python scripts/check_closeout.py <根>`
- 有 git 时，「改动点」每条附 commit hash；需要完整 diff 时 `git show` 即得

### 4.3 最小交接（minimal handover — 6+1 块）

块名**冻结**（是门禁的逐块校验对象）：
`本次需求 · 本次涉及工程信息 · 改动点 · 验证结果 · 数据影响 · 下一步 · 任务卡更新`

第 7 块「任务卡更新」**有对应任务卡时必填**。不贴 diff、不复制代码。

### 4.4 命名规范

- 记录：`YYYY-MM-DD_主题_AI标识.md`（写前先 list 目录确认无同名）
- AI 标识：`{平台}-{机器码}`，可选追加 `@<角色槽>`；**由 `scripts/stamp.py --ai-id` 产生，AI 不得自报**。
  机器部分在同一台机器上恒定（旧规「主 AI 标识固定」由约定改为由构造保证）；角色槽从 MAP 登记表取值，**禁止写人名**
- 任务卡：按工作命名

### 4.5 档案红线

**禁止删除/移动 `reports/` 与 `archives/` 下任何文件**。
唯一例外＝归档流程（超阈值滚动归档、完成归档任务卡），且**移后必须同步索引对应行指向**。

---

## 5. 归档（archive）

- **完成卡**：`tasks/` → `archives/done/`，**不覆盖同名目标**
- **记录滚动归档**：篇数达 MAP 规则段「reports 归档阈值」即按日期从旧到新移入 `archives/`，**行永不丢失**
- **归档算法**（原子性要求）：先写归档临时文件并校验 hash → 原子替换归档文件 → CAS 更新热区。
  **任一步失败则保留原热区文件**，留下冲突文件与元数据通道事件，**不得宣称完成**。

---

## 6. 元数据通道（meta channel）

技能自身事务（复盘、版本漂移检测、恢复动作登记）**一律追加写 `REVIEWS.md`**，
**不写 `reports/`、不登 `INDEX.md`**——项目档案只存项目工作记录。

---

## 7. 人眼查看视图（人类查阅约定 · 平台无关）

- **默认先展示整个目录结构**（tasks / reports / INDEX / REVIEWS / archives / tools 一眼全貌），人先看全貌、再点进某处。
- **两个粒度**：
  - 近期 → 读 `INDEX.md` 热区（仅最近若干行，条数见 {{config:capacity.index_hot_rows}}）
  - 全部历史 → **仅用户明确要看全部时**才读 `archives/INDEX_archived.md`
- **按目录逐项查看**：项目总览 / 工具区 / 全部记录 / 历史追溯 / 决策点 / 任务卡详细 / 元管理详细。
- **呈现约定**：能打开文件/目录的平台 → 提供「打开」入口；无此能力 → AI 读后以表格/列表输出；无交互选择 → 直接列出全部由用户口述选择。
- **热区行数标注话术**：提交时在记录里标注索引热区当前行数——未满配置值只显示数字；满配置值时提醒可调整（冷区有完整记录可追溯），用户确认后改 MAP 配置，**归档记录不受影响、历史追溯不断**。
