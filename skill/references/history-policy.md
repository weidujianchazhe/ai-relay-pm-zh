# 历史不得耦合（协议）

> **本文是规则，不是历史。** 它规定「历史记录」与「协议规则」如何分离，防止历史负担变成功能耦合。
> 历史记录本身**不写在这里**——它在 `references/archives/`（**非协议正文**，见 `MANIFEST.md` 的分层）。

## 1. 两类东西，两个去处

| 判据（看这句话有没有时间与事件）| 属于 | 去**正文** `references/*.md` | 去**历史册** `references/archives/` |
|---|---|---|---|
| 有「某次 / 曾经 / 此前 / 上一轮 / vX.Y / 日期」等**时间或事件** | **历史** | ❌ 不进 | ✅ 进 |
| 只陈述「**必须 X（否则 Y）**」「**度量的是 A，不是 B**」 | **规则** | ✅ 进 | ❌ 不进 |
| 两者都有 | **混合** | ✅ **只留规则**（去掉时间与事件）| ✅ 过程进此处 |

> ★ **一句话**：**含时间就是历史，去时间才是规则。**

## 2. 三条禁令

1. ★ **任何规则都不得只存在于历史册。** 若某条历史里有可复用的约束，**必须提炼进正文协议或检查脚本**；
   历史册只留「那次发生了什么」。
2. ★ **历史册不得进入接手路径。** `SKILL.md` **不为它加路由**；接手者**不需读**它。
3. ★ **历史册不得被机器读取为规则依据。** 脚本不解析它、门禁不依赖它 —— 它是**人查的档案**，不是**机器的输入**。

## 3. 出现历史负担时的处置（四步）

```
① 认出它：这段文字有时间和事件（不是规则）
② 问一句：它现在对应的【规则 / 检查】是什么？
    · 有  ⇒ ③ 只留规则，过程迁走
    · 没有 ⇒ ③' 先补规则（正文条款或检查脚本），再迁走
③ 迁走：移入 `references/archives/`，在正文留一行指针（如需）
④ 验证：`gen_views` 全绿（历史册不在正文校验范围内）
```

> ★ **判据**：迁走后，**正文里不再出现那次事故的时间与情节**，但**它带来的约束仍然生效**（写在条款或脚本里）。
> 如果迁走后约束也随之消失，说明**你迁走的是规则，不是历史** —— 必须迁回正文。

## 4. 为什么必须这样

> **历史一旦参与耦合，就会成为莫名其妙的 bug 产生点**：后来的读者把「当时为什么这么做」当成「现在也必须这么做」，
> 或者反过来，把一段过时的描述当成现行规则。
> **规则必须是**无时态的、可判定的、只有一个当前真值；**历史必须是有时间、有情节、只供查证**。两类东西混在一起，两边都会失真。
