# 术语表（Glossary）

> **何时读**：看不懂某个词、或要改叙述文本时。
> **两条纪律**：
> ① **产物名 / 字段名 / 块名 / 目录名一律冻结**——它们是脚本的功能接口（见 `references/change-control.md` §0）。
> ② **叙述文本用标准软件工程术语**——本表提供对照，便于接手者不必先学一套私有词汇。

## 一、冻结清单（**禁止改名**，改了会破坏功能）

| 类别 | 冻结值 | 谁在消费它 |
|---|---|---|

## 二、叙述术语对照（自造词 → 标准术语）

> 表中"原词"在**旧实例**里仍可能出现；**新写文档一律用标准术语**。

| 原自造词 | 标准术语（推荐用词） | 出处/依据 |
|---|---|---|
| 收工四件套 | **提交流程（closeout checklist）** | 交付前固定检查清单；Scrum/XP 通用 |
| 收工分流 | **提交流程分派（closeout routing）** | 按"是否有后继"分流 |
| 提炼回卡 | **摘要写回（write-back）** | 避免重复读源；缓存写回同义 |
| 覆盖式更新 | **原地更新（in-place update）** | 不追加历史、只留最新 |
| 双写 | **镜像写（mirrored write）** | 冗余防丢 |
| 锚点（**现役**：卡字段名/通用词，勿替换） | **引用 / 指针（pointer）** | 指向文件或记录 |
| 接手成本 | **上手成本（onboarding cost）** | 新人/AI 达到可开工状态的成本 |
| 承接（**现役**：卡字段名/通用词，勿替换） | **认领（claim）** | 任务所有权声明 |
| 落点即覆盖 | **检查点写回（checkpointing）** | 中断可恢复的最小状态落盘 |
| 元管理分流 | **元数据通道（meta channel）** | 技能自身事务与项目记录分离 |
| 变更保护区 | **变更控制门禁（change control gate）** | 影响分析前置门禁 |
| 方案文档 / 设计说明书 | **设计详述（design spec）** | 设计的**叙述**部分（权威源，长）；与蓝图的分工见 `references/design.md` §1 |
| 架构图 / 示意图 / 概览（**现役**：卡字段名/通用词，勿替换） | **设计蓝图（design blueprint）** | 设计的**结构**部分（一屏可扫，给人看）；后缀 `.blueprint.md` 冻结 |
| 承重结构 | **不变量（invariants）** | 不得删除/弱化的语义保证 |
| 对账（**现役**：卡字段名/通用词，勿替换） | **一致性校验（reconciliation）/ 审计（audit）** | 多记录互证 |
| 封顶装置 | **容量上限（capacity cap）** | 阅读成本的封顶值 |
| 撞号 / 让号 / 号段预留（**现役**：卡字段名/通用词，勿替换） | **ID 冲突 / 让位 / 号段分配**（collision / yield / range allocation） | 分布式编号常规问题 |
| 派发摘录（**现役**：卡字段名/通用词，勿替换） | **任务简报（task brief）** | 下发给执行者的上下文切片 |
| 主文件 / 归档文件（**现役**：卡字段名/通用词，勿替换） | **热区 / 冷区（hot / cold tier）** | 分层存储 |
| 分层读取 | **分层读取（tiered read）** | 常用在前、全量在后 |
| 白话对照 | **术语表（glossary）** | 标准叫法 |
| 单写者责任 | **单写者原则（single-writer principle）** | 每份数据同时只有一个写者 |
| 条目级写 | **字段级更新（field-level update）** | 并发下只改自己那条 |
| 移卡 | **归档任务卡（archive the card）** | 完成后移入冷区 |
| 认领 → 干活 → 收工 | **认领 → 作业 → 提交（claim → work → closeout）** | 工作生命周期三段 |
| 冗余/重复的文档（**现役**：卡字段名/通用词，勿替换） | **文档腐化（documentation rot）** | 与代码腐化同源 |
| 屎山（**现役**：卡字段名/通用词，勿替换） | **技术债 / 结构腐化（technical debt / structural rot）** | 标准叫法 |

## 三、旧名对照（存量实例升级用）

> **本表用途只有一个：读存量文件时把旧名对上。**
> **不得据此回写历史记录**——旧标识与旧字段是那些记录**当时真实的内容**，
> 批量改写等于伪造痕迹，与 `references/audit.md` 的诚实边界相抵触。
> **存量记录保持原样，不做迁移**：旧记录继续按旧名读，新记录按新形写，两者可在同一工作区并存。
> **本节是「有意的跨文件内容」，不是冗余——不得以"包内 0 引用／去重"为由删除**：
> 它的读者是**持有存量工作区的人**，不是包内脚本。**包内引用数不是价值判据。**

| 更早的叫法 | 现行 |
|---|---|
| 最后折叠 | 已提炼 |
| 工程锚点（**现役**：卡字段名/通用词，勿替换） | 代码根路径 |
| 技能资产层（资产层） | 技能源包 |
| 锚点组（**现役**：卡字段名/通用词，勿替换） | 已并入「上次交接」说明 |
| 沉淀再前进 | 摘要写回（原：提炼回卡） |
| 即时复制型 / 落盘接取型 | 未建卡的工作 / 已建卡的工作 |
| 派生视图 · 机械重写（**现役**：卡字段名/通用词，勿替换） | 人读区由 AI 区自动生成 |
| 内容级并发安全 | 并发写规则 |
| 前置查重 | 先查重 |
| 树链式 | 按模块/分支分工 |
| 双阅读层 | 人读区 + AI 区 |
| 认路总图 | 项目地图（MAP） |
| AI 标识里的「AI 名 - 短码」 | 机器产生的 AI 标识 `{平台}-{机器码}[@{角色槽}]` |
| 人检标记的「owner / next」 | `slot`（角色槽）+ `by`（机器戳），到期由戳推导 |
