# 恢复（Recovery）

> **何时读**：文件丢失 / 内容损坏 / 指针断链 / 版本过时 / 归档不一致时。
> **第一原则**：**数据诚实边界**——恢复不出的内容标「数据待补」，**禁止伪造**。

---

## 1. 恢复总则

```
① 只读勘查    先盘清"有什么、缺什么"，不动任何正式文件
② 生成候选    产出恢复草稿，标注证据与不确定处
③ 人工确认    覆盖正式文件前必须经确认
④ 留痕        任何恢复动作随即记一行 REVIEWS.md（元数据通道）
```

**恢复 AI 的权限边界**：只读生成候选与证明、经确认才写恢复草稿；**禁止无确认覆盖正式文件**。

---

## 2. 缺失补全（missing-file completion）

技能源包为权威源：项目工作区文件**缺失或过时**（源包版本更高）→ 从源包复制模板实例化重填。

恢复时每个候选源都要记录：

| 项 | 说明 |
|---|---|
| 路径 | 候选源在哪 |
| 读取时间 | 何时读的 |
| 编码 | UTF-8 / UTF-8-BOM / GBK … |
| RAW-SHA256 | 原始字节哈希 |
| NORMALIZED-SHA256 | 统一 UTF-8、换行、去 BOM 后的哈希 |

**无法证明的字段标「数据待补」，不伪造。**

---

## 3. 断链修复（dangling pointer repair）

- **断链** ＝ 卡「上次交接」/ 索引「交接文件」指向的文件不存在
- 先在 `INDEX.md` 与 `archives/INDEX_archived.md` 按主题/日期找实际位置（文件可能已被归档）
- 找到 → 修正指针；**找不到 → 指针改「数据待补」，不伪造**
  > **冷区（`archives/INDEX_archived.md`）的修改属于「归档 / 恢复流程」的允许例外**——但**必须经 `closeout.py` 或 `lease` 原语写入**；手工直改会被漂移检测判红（见 `references/artifacts.md` §2 冷区不可变）
- 工具：`scripts/reconcile.py` 会列出全部断链

---

## 4. 快照恢复（STATE recovery）

- 素材来源：最新含「下一步」的记录 + `tasks/` 现存卡
- 产出**重建草稿**并标注「待确认」，**不直接落成正式文件**
- 正式覆盖前必须经用户/管理者确认

---

## 5. 版本过时（version drift）

- 比对工作区 `MANIFEST.md` 声明的版本 vs 技能源包版本
- 源包更高 → 提示拉取更新；**工作区更高 → 说明存在未回流的本地扩展**
  （实例版本高于源包，说明本地扩展未回流）
- 版本一致性由 `scripts/gen_views.py` 校验

---

## 6. 归档一致性（archive consistency）

- 冷区应**全量**、热区应是其**尾部子集**
- 热区被移出的行必须**在冷区找得到**（"移入不删除"）
- 归档算法任一步失败 → 保留原热区、留冲突文件与 REVIEWS 事件、**不得宣称完成**

---

## 7. 任务卡重建（card rebuild — 草稿脚手架）

**场景**：任务卡丢失或损坏，但有索引行与记录可循。

```
① 线索来源   索引 [接力] 行的「交接文件」列 + reports/ 按日期倒序的候选
② 语义字段   描述 / 要点 / 已提炼 —— **必须读候选记录补全，禁止凭印象编**
③ 输出形态   重建草稿（标「待确认」），**不直接落成正式卡**
④ 人工确认   用户/管理者确认后才成为正式卡
```

**为什么不做成脚本**：字段语义只能靠读记录理解，属**草稿生成**而非确定性判定——
脚本在此只会产出"看起来对"的假卡。**这类工作留给 AI + 人工，不给机器。**

> 若索引 [接力] 行为空，说明当前无活跃接力链，通常无需重建；
> 先确认是否只是"卡被误移到归档"（查 `archives/done/`）。

---

## 8. 源包对照还原（reference reconstruction）

多记录互证，**对的是一致性，不是直接还原信息**：

```
① 协议正文          从任一项目工作区逐字对照还原——工作区随带 `SKILL.md` + `references/` 逐字副本
                    （初始化时原样复制进工作区；旧版工作区只带 `SKILL.md`，正文走 ②）
② 无工作区副本的    按 MAP 登记的备份方式取回；取不回的标「待补」不伪造
③ 还原后            跑版本一致性校验 + 记 REVIEWS.md
```

**对账不一致处凭痕迹分析推导，允许部分还原，禁止凭印象补写。**
