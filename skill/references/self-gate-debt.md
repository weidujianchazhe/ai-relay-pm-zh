## 2. 范围声明：本包 `scripts/` 不计入本包对外的代码质量门禁

**状态：已声明 · 未豁免判定语义 · 未调整任何阈值。**

`scripts/` 是**本包自带的工具脚本**，与「被管理项目的业务源码」不是同一类对象；
用同一套阈值直接判红会把工具自身缺陷与项目质量混为一谈。本声明只界定**适用范围**：

- **不提高阈值**、**不关闭检查**、**不改判定语义**；
- 违例**保留完整可见**（任何人跑 `python scripts/code_metrics.py scripts` 都能看到）；
- 若将来要把 `scripts/` 纳入对外门禁承诺，**必须先完成**剩余整改（按性价比排序）。

**当前读数（2026-10-02）**：拦截线 **0** · 非规模 `[问题]` **0** → **本包自门禁债已清**；
`scripts/` 的规模类命中仍逐条打印（观察级），供重构参考。

### 附：字节码残留口径（`__pycache__` 一律不留）

**决定：保住「副本不留 `.pyc`」这条口径**，并用 `-B` 让它**可复现**，而不是靠打包顺序的运气。

实测分层（2026-10-02，清 `__pycache__` 后各跑一次）：

| 跑法 | 残留 `.pyc` |
|---|---|
| `python scripts/selftest_gates.py`（顶层裸跑） | **3**（`lease` / `locks` / `_common`） |
| `python -B scripts/selftest_gates.py` | **0** |
| `python scripts/audit_all.py .`（顶层裸跑） | **4**（多 `stamp`） |
| `python -B scripts/audit_all.py .` | **0** |

**结论（必须如实记）**：残留**完全由顶层解释器决定**——`python <脚本>` 形式下脚本自身作为
`__main__` 从不被缓存，写入的是**父进程导入链**上的模块。因此：

- **顶层 `-B` 是决定性的**（CI 5 处已加；`scripts/README.md` 已写明「运行包内脚本一律 `python -B`」）；
- **子进程 `-B`（11 处）在当前包内无可观测收益**，属纵深防御：只有当某模块**仅被子进程导入**时才生效，
  而现有调用形态下父进程导入链已覆盖全部模块。**不夸大它的作用。**

**为什么不是「用有利环境替包打掩护」**：`gen_views` §15 自 P0-1 起**已不把 `__pycache__`/`.pyc` 判为残留**，
门禁对该目录无任何判定——`-B` 掩不住红灯，只管卫生。与历史上「每次带 `PYTHONDONTWRITEBYTECODE=1` 跑 `--check`」
是**两件事**，不可混淆。

## 4. 制度性脆弱：字符串判据（四次实例，长期保留）

1. **门禁身份靠关键词判定**：`check_promises` §1 名单 = `README` 描述含「门禁」二字者 → **漏词即漏管**
   （实例：`correctness_rules.py` / `check_size_budget.py` 曾因此长期不在存活检查内）。
2. **失败通道是【或】判据**：`problem( OR tbd( OR print("[失败]")` ——**只删其一无法让检查变红**，
   对照变量会被短路（本会话我用只删 `problem(` 做变异 → 得出**错误结论**；复核方用「干净双删 + 对照组」才定论）。
3. **子串判定易被骗**：用「源码含『失败』二字」代替精确字面量时，被「（失败原因不可定位）」与
   「解析失败」骗出两个假结果 → 判据必须是**精确字面量**。
4. **自检判据过宽（退出码被当成布尔）**：`selftest_gates` 原判据是「`rc == 0` 才算没变红」，
   即**任何非零都算自证通过**；而退出码 `3 = 脚本/用法错误`。于是「把脚本跑崩了」可以冒充
   「门禁抓到问题」——**同一类输出上无法区分**。
   已修：只认 `1`（阻断）/ `2`（仅待核）为「已变红」，`rc == 3` 判**用例失败**并单独报出。
   （收紧前实测 19 个用例变异后退出码全为 `exit=1`，故收紧**零误伤**。）

**共同教训**：凡判据靠字符串存在性（词 / 子串 / 或），都必须配一次**变异自证**；
否则「检查通过」与「检查没在管」在输出上**无法区分**。

## 5. 三器失准：验证基础设施自身的缺陷族（实测 · 已成立）

验证系统的故障域**不止被测对象**。本包实测到的因果链：

```
三器失准
  ├─ 生成器失准（承载/语法层）      → 脚本在解析期失败，事务链未启动（WRITE=0）
  ├─ 测量器失准（计数/口径层）      → 机制正确却被计成失败（如把"豁免"计成"G1 命中"）
  └─ 夹具失准（构造/前置层）        → 夹具不满足真实谓词，规则不触发被误读为机制失效
        ↓
   假阴性 / 假阳性 / INVALID
        ↓
   必须先判定"验证基础设施是否有效"，再判定被测对象
```

**核心规则（已实测成立，非未来建议）：**

- **⑫ 可比对象有效性**：`EXPECTED_SUCCESS ∧ OUTPUT_CARDINALITY ∧ OBSERVATION_DOMAIN ⊇ 实际输出域`；空集比较不得产生 PASS。
- **⑬ 环境等价关系 E**：证明的是 `RAW_OLD ≈_E RAW_NEW`；`E` 必须显式、有限、可审计，并保留原始值与归一化值。
- **⑭ 夹具真实性**：先读实现取真实触发谓词，夹具前置逐项对齐；不满足 → INVALID，不得进入机制测试。
- **⑮ 验证方向完整性（正控缺口）**：**只证明「坏东西能被拒绝」，不等于证明「好东西能被接受」。**
  **技术债**：`selftest_gates` 的验证方向不完整。
  **现状**：当前 `19/19` 的通过语义**仅**证明「19 个破坏注入均能使目标门禁变红」，
  **不**证明对应门禁在正常、合法输入下能够保持绿色。**★ 19/19 ≠ 正常态可绿。**
  **实测证据**：P0 `[待填]` 占位计数曾存在**正常态永久报红**（真实骨架 7 处 `[待填]` 中 1 处为脚本说明行、6 处为真占位；
  旧逻辑全文计数 → 人补齐 6 处后仍报 1 处、无法提交）；由于自检采用「注入后必须变红」的判据，**该缺陷在 19/19 下仍全部通过**。
  **边界**：这是**验证基础设施的盲区**，**不代表现有 19 个负控用例无效**；现有负控**继续保留**。
  **后续方向**：如未来修正验证基础设施，应补充对应**正控**——**撤销破坏注入后，正常基线必须恢复绿色**。
  **当前不新增测试框架、不新增门禁**（本条仅为技术债事实登记，非规范、非测试要求）。

### 附：假阴性登记（保留，避免重犯）

- **工具调用失败 ≠ 事实缺失**：`glob` 返回 0、路径拼接报错、检索命令无效 —— 均属**调用层失败**，
  不得据此断言"文件不存在 / 锚点缺失"。必须先用**已知正确样本**自检工具调用是否有效（如"已知 SHA 必须能取到并一致"）。
- **测试自己声称"全绿"不是证据**：结论必须能由它自己输出的原始事实推出（`RAW → … → EXIT` 任一环脱钩即不成立）。
