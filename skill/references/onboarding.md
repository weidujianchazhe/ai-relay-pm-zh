# 首次接入与工作区形态

> **何时读**：新项目的**第一次对话** / 存量项目接入 / 判断"这个项目要不要建完整工作区"时。
> **读一次的代价换整条链路的成本**：形态定错，要么背着一套没人维护的空档案，要么中途返工重建。

---

## 1. 第一次对话第一件事：判定形态（三选一）

| 形态 | 适用 | 产物 | 需要跑的门禁 |
|---|---|---|---|
| **卡片模式** `card` | 一件工作、短周期、单人单 AI、一个对话窗能做完 | **一个卡片文件**（无工作区、无索引、无快照） | 无（人读卡即可） |
| **轻量工作区** `light` | 长周期但单线推进，不需要分工与审计 | 工作区 + 任务卡 + **交接记录** + 索引（＋ 按需的设计区） | `check_closeout.py`（提交前）+ `check_index.py` |
| **完整工作区** `standard` / `coordination` | 长期、重、多 AI、需要交接与审计、一个对话窗做不完 | 全部产物（见 `references/artifacts.md` §1） | 全套 `scripts/` |

**判定问句（按顺序问，命中即停）**：

```
① 这件事**一个对话窗能不能做完**？          能   → 卡片模式
② 会**跨会话 / 跨天 / 跨 AI** 吗？            不会 → 卡片模式
③ 需要**多方同时写**或**可审计的交接**吗？    不需要 → 轻量工作区
④ 以上皆是                                  → 完整工作区
```

> **从严到宽，不从宽到严**：先按能跑的最小形态起步，**发现不够再升**（升级即扩集，历史不回写）。
> 反过来先建全套再降级，只会留下一套无人维护的空档案——**空档案比没有档案更坏，它制造"已管理"的错觉**。

**判定记在哪**：形态写入 `MAP.md` 规则段的「协作模式」行——**light 与 standard 都写 MAP**（light 的规则段项少而已）；
**卡片模式没有 MAP**（见 `references/collaboration.md` §1 的形态表），此时形态记在本轮对话与首份报告里；**light 有 MAP**（机检 `validate_workspace` 把 MAP 列为必需文件）。
升级时改这一行即可，**历史不回写**。

## 2. 卡片模式（`card`）——不建工作区也能接力

**一个文件就是全部。** 放在任意位置（项目根、或 `tasks/` 若已存在），文件名即工作名。

**卡的样子**：见 `templates/CARD.md`——**它是单文件工作卡的唯一模板**，本文件不复述副本。

**字段名与工作区任务卡同名同义**（冻结值见 `references/artifacts.md` §2）：
`编号 · 状态 · 代码根路径 · 涉及 · 承接 · 进度锚点 · 上次交接 · 下一步`，外加一段**追加式**「交接流水」。

**规则（只三条）**：

1. **追加不覆盖**：交接流水**追加**，不重写历史。
2. **每篇接头最多被读一次**：读完后把增量写进「进度锚点」与「下一步」，别让下一位重读流水。
3. **完成后不改内容**：状态改「已完成」，文件留在原处——**它自己就是记录**。

**明确不做**（这是卡片模式的定义，不是缺陷）：无索引、无快照、无并发控制、无归档、无门禁。
**什么时候必须升档**：出现第二个 AI 同时写、或流水超过约一屏、或需要"谁在做什么"的全局视图时。

## 2.9 启动段（定死 v2）· 新建项目 / 接管项目 的固定流程

> **本段已定死**：不得增删步骤、不得改变问法；**不得因为拿不到值而跳过或自行编造**。
> **优先级**：**段 1（选路径）最重要** —— 存储放错代价最大，故写得最死；段 3/4 是功能展示，可略宽。
> **底座适配**：弹窗不可用、或承载不了自定义输入时，**值类问题改在对话里问答**；选项类仍可用弹窗。**不得因此跳过或编值**。

### 步 0 · 判定形态（三选一，AI 判定）

按 `§1` 的四句判定问句（一个对话窗能否做完 / 跨会话跨 AI 吗 / 需多人同写或可审计交接吗 / 以上皆是）**从严到宽、命中即停**。

| 形态 | 之后怎么走 |
|---|---|
| **卡片模式** `card` | **跳过段 2**（不建管理区、不展开技能）：只产出**一个卡片文件** `CARD.md`，流程到此结束 |
| **轻量** `light` / **完整** `standard` | 进段 1 -> 段 2 -> 段 2.5 -> 段 3 |

### 段 1 · 选工作区 / 命名项目（最重要）

| 步 | 必须做的事 | 停止条件（不满足就**停在本步**） |
|---|---|---|
| 1.0 | 触发：用户说「新建项目 / 用这个技能做 X」，且该项目**尚无管理区** | 已有管理区 -> 走 §3.6「接手已有管理区」 |
| 1.1 | 问「**项目放哪**」（必填、**无跳过键**）：给**两个可点选项** —— A「用默认工作区（<当前工作区路径>）」／B「另起目录」 | 未给出 -> **留在本步** |
| 1.2 | 若选 B：**必须再问一次路径**（无跳过键），拿到**立即校验** | 路径为空 / 目录不存在（悬空）-> **拒绝并重问** |
| 1.3 | 问「**项目名**」（必填、无跳过键）：给**两个选项** —— A「用工作区名（<工作区目录名>）」-> **解析成实际值并回显**／B「我自己输入」 | 名称为空、或不像名字 -> **留在本步** |
| 1.4 | **三项校验**：① 存在性（悬空拒绝）② **非空不阻断**（工作区天然非空）③ **同名查重**（`<项目名>` / `<项目名>-管理区` 已存在 -> 复用或确认唯一正本，**禁止另起**） | 同名 -> 先查重 |

**本段禁止**：只给一个空白输入框；给「跳过」键；**拿选项文字当值**；名称为空仍前进；**拿不到就自己编名字**；**值拿到后不回显就落库**。

### 步 1.5 · 技术栈选择（默认 Python）+ 环境前置确认（**在初始化管理区之前**）

| 选项 | 之后怎么走 |
|---|---|
| **① Python（默认）** | 无额外环境要求，直接进段 1（**绝大多数用户感觉不到这一步**） |
| **② 其他语言（从清单选）** | 先列出现有语言供点选：**C · C++ · JavaScript · TypeScript · Java · Go · Rust**（以及 `adapters/` 里已建立的其它栈）→ 写 Project Profile（语言/构建/测试/工具链/目标/取数探针）→ **Environment Preflight**：只**检查**用户环境，**不安装**；缺工具 → **先告诉用户缺什么**，相关能力报 **[待核]** |
| **③ 自定义（自己填）** | 用户直接写语言/技术栈名（含内部 DSL、公司自有语言）→ 按该栈声明 Profile；工具缺失一律 **[待核]**，**技能不代装** |
| **④ 跳过语言选择** | **先做设计卡，后定语言方案**：设计阶段不绑语言；设计定稿后再回到本步补 Profile（届时按 ①②③ 任一路径） |

> **问法（强制：拆三问；互斥项不得同组）** —— 两条**实测暴露**的坑：
> **坑一**：「跳过」与「定语言」**语义互斥**，放进同一多选组会让用户**同时选中两者**（实测已发生）。
> **坑二**：把 ① Python 与 ② 其他语言**合并成一个语言列表**，用户会问「**这里没有 Python 啊**」（实测原话）；**默认项必须显式可见**。
>
> **第一问（单选）**：现在定语言方案吗？ → **【现在定】** ／ **【先跳过】**
> **第二问（仅选【现在定】时，单选）**：**① Python（默认）** ／ **② 其他语言** ／ **③ 自定义（自己填）**
> **第三问（仅选【② 其他语言】时，多选）**：
>   · **C · C++ · JavaScript · TypeScript · Java · Go · Rust** —— 以 **`adapters/` 目录为准**（**数量不写死在此处**，防手工清单漂移）
>   · **「我想要看看语言目录」** —— 指向 `references/language-adapters.md` 的**语言适用性路由表** 与 `config/providers.json`（**档案正本**：语言/资产/数值/待接入四类，**逐条带状态**）；**只指路、不复述**，**数量以正本为准、不写死在此处**
>   · **「自定义」** —— 提示：**不在清单里的语言/技术栈**（含内部 DSL、公司自有语言）**直接写名字**；**未接线的一律报 `[待核]`**，**不影响先开工**
>
> ★ **「先不定」不在这里** —— 它只在**第一问**（【先跳过】）；第三问若再放一个跳过，就会出现两个跳过的语义歧义。
>
> ★ **Python 只出现在第二问的 ①，不得出现在第三问清单里**；**每问单选；只有第三问清单可多选**。
> 选【先跳过】→ **不问第二、三问**，不写 Profile，MAP 记 `language: unset`。

> **四选项的共同口径**：**登记 ≠ 支持**；未接线一律 `[待核]`（**不适用 ≠ 不合格**，不要去"修"它 —— `code-quality.md` §0.2）。选 ④ 时不写语言 Profile，Profile 留空并在 MAP 记 `language: unset`。

> **契约**：技能包**不携带、不自动安装**工具链（七条原则见 `references/language-adapters.md` §9）。
> **只在第一次问**：Profile 写入 MAP 规则段后，后续 `BUILD/TEST/AUDIT/VERIFY` 直接按 Profile + 实测环境执行，不再追问。

### 段 3 · 设计卡（功能展示）

| 步 | 必须做的事 |
|---|---|
| 3.1 | 问「设计卡：怎么办？」**三项**：① **建一张设计卡**（卡名**与建卡同档给、强制填、无跳过键**；空 -> 重问，**第 2 次只给「先不建卡」**）② **先开始设计**（不建卡）③ **先不设计**（跳过 -> **立刻接段 4**） |

| 3.4 | 定稿后 **AI 自行拆分**（小任务 1 张 / 大任务多张）-> 任务卡**回填 `DESIGN-ID = DSN-…`** |

| 步 | 必须做的事 |
|---|---|
| 4.1 | 问「任务卡：怎么办？」**三项（用户语言）**：① **先开始做** ② **建一张任务卡** ③ **先不建任务卡** |
| 4.2 | 选② -> 问卡名（**纯命名，不放反悔项**）；空、或不像名字 -> 停在本步 |
| 4.3 | 建卡时**显式记录** `DESIGN-ID = 先跳过`（机检：`new-task --skip-design`，见 `closeout.py new-card --skip-design`） |

### 提问规范（跨段通用 · 五条）

1. **不替用户命名**：值类只给「我自己输入」入口；确需举例必须写「**例：**…」并明确**示例不会被采用**。
2. **选项不得含可直接落库的值**：建卡 / 建设计卡类选项**只写动作**，不写具体名字。
3. **默认必须惰性**：默认选项**不得产生创建副作用**；未明确确认就**不建**。
4. **值类问题必须开放式提问**：点选确认 -> **收到非空值** -> 才进下一步；空 -> **留在本步追问**并**明确回执**。
5. **流程必须连续**：跳过某环节 -> **立刻接下一环节**；**不许输出一句就停**；**未选 = 停住**，不默认走任何一支。

### 面向用户的语言（硬约束）

**面向用户的选项必须用「用户视角」的语言**；技能内部概念（建卡 / 不建卡 / 落库 / DESIGN-ID / 先跳过）**不得出现在选项文案里**。

- ✅ 正确：`① 先开始做` `② 建一张任务卡` `③ 先不建任务卡`
- ❌ 错误：`先不建卡`、`先跳过（内部逻辑）` —— 把技能逻辑词当选项。

## 3.6 接手已有管理区 · 照读话术（五步）

> 适用于**已经有一个管理区**的场景（新 AI 接手别人的项目）。**必须按序**，且**只追加、不改历史**。

```text
① 查重 + 唯一正本：管理区 MANIFEST/MAP 已存在？存在 → **不另起**，接手 = 读它、往里追加
② 读五个落点（只读，按此顺序，不要全读）：
     1) MAP.md 规则段     → 本实例取值（协作模式 / 上限 / 定期排查开关）
     2) STATE.md 决策点   → 悬而未决的问题
     3) INDEX.md 末行     → 上一次交接在哪
     4) reports/ 最新一条 → 上次做到哪、什么没做、下一步
     5) tasks/ 状态=进行中的卡 → 承接人是谁、要点完成几项
③ 跑 check_closeout.py <管理区> → 交接口径机检（6+1 块不全 / 占位符 / 时间戳）
④ 出「接手摘要」给用户（**必须先给再动手**）：我理解了什么 / 未闭环项 / 建议下一步（给选项，不擅自开工）
⑤ 只追加登记：往 REVIEWS.md 追加「接手登记」（历史一字不改）
```

## 4. 脚本就位：复制即用，无需初始化

**结论：`scripts/` 原样复制进工作区即可，没有任何"初始化脚本"这一步。**

| 常见疑问 | 答案 |
|---|---|
| 要不要按项目生成脚本？ | **不要**。脚本是通用门禁，不含项目专属逻辑 |
| 要不要改脚本里的路径？ | **不要**。所有路径都从命令行参数取（`<管理区>` / `<源码根>`） |
| 要不要先跑一次"安装"？ | **不要**。仅依赖 Python 3 标准库，无第三方、无编译、无配置 |
| 阈值改在哪？ | 改 **`MAP.md` 规则段**（或实例 `config.yml`）——脚本按"实例优先、出厂默认兜底"取值，**不改脚本** |

**用法固定**（完整清单见 `scripts/README.md`）：

```
python scripts/validate_workspace.py <管理区>    # 建好/改结构后
python scripts/check_closeout.py     <管理区>    # 每次提交前
python scripts/check_index.py        <管理区>    # 改索引后
python scripts/reconcile.py          <管理区>    # 定期
python scripts/code_metrics.py       <源码根>      # 每次改代码后
python scripts/closeout.py           <管理区>    # 提交时的机械步骤（见 references/workflow.md §4.2）
python scripts/audit_all.py          <管理区>    # 全盘核查 + 留痕（工作流之外，用户自检用）
python scripts/stamp.py --ai-id                    # 认领任务卡时
```

**说明**：门禁由**执行脚本**给出，不再由**读文档判断**给出。
接手者不需要读完规范才知道什么算合格——**跑一次，看退出码**（**仅限基线已冻结之后**；
**存量项目首轮只做只读盘查，不作阻断**——见 `LEGACY_ONBOARDING.md` §五.7）。
省下的是每次接手都要重读规范的那部分上下文。

### 4.0 按形态跑哪些脚本（先看这张表，再看下面的命令）

**脚本不是"装了就全跑"**——跑哪些由**形态**决定。多跑的部分不只是浪费，还会制造噪声（比如给只有 MAP 的项目报"缺快照"）。

| 形态 | 提交时 | 核查时 | 一次性 |
|---|---|---|---|
| **卡片模式**（一个文件） | **不跑任何脚本**——提交流程＝追加一行交接流水 | — | — |
| **轻量工作区** `light` | `closeout.py`（记录骨架 / 卡归档 / 索引镜像写）→ `check_closeout.py`（**门禁，失败即阻塞**） | `check_index.py`（改索引后）· `overview.py`（随时，秒级，恒 0） | — |
| **完整工作区** `standard` / `coordination` | 同上（提交四项里多一项快照，由人改） | 上表全部 ＋ `reconcile.py`（三方一致）· `validate_workspace.py`（改结构后）· `audit_all.py`（定期，默认 7 天，**编排全部并留痕**） | `setup.py --plan`（首次四问）· `new_local.py`（要项目专属检查时） |
| **只写代码**（只要规范） | — | `code_metrics.py`（每次改代码后） | — |

**两条纪律**：

- **门禁只认退出码**：脚本跑完看退出码（0 通过 / 1 有 [问题] / 2 仅 [待核] / 3 脚本自身错误），**不靠读输出自我判断**。
- **形态决定项数**：light 的提交流程是**三项**（记录 / 卡 / 索引），**没有快照那一步**——所以 `check_closeout.py` 在 light 下不会因为缺 `STATE.md` 而报红（设计上恒定成立的项一律降级为 [建议]）。

### 4.1 项目自定义脚本（`scripts/local/`）

技能包装的是**通用**门禁；项目自己特有的判据放 `scripts/local/`。

```
python scripts/new_local.py <管理区> <脚本名> --purpose "<一句话用途>"
```

生成 `scripts/local/<脚本名>.py`：三态输出 / 退出码 / 参数解析 / 汇总**已就位**，只留一处 `TODO` 写判据。

**三条红线**（详见 `scripts/local/README.md`）：
① 不改包内 `scripts/*.py`——改它下次升级会丢；② `local/` 的产物**不进技能包**；③ `local/` 不得把包内门禁判红的结果改绿。

> **口径**：**通用检查随包给实现，项目专属检查给脚手架**——样板由机器生成，人只写判据。
> 若只给一份"规格"让 AI 临时造脚本，结果必然是每个项目手写一遍样板，且造出的脚本弱于规格。

## 5. 建区完成后：配置向导（问三件事）

> 位置：本向导在 **段 2 建区完成后**执行（需要管理区已存在）。

```
python scripts/setup.py <管理区> --plan      # 出询问单 → AI 拿去问用户
python scripts/setup.py <管理区> --apply --git yes --audit-days 7 --commit
```

| # | 问什么 | 推荐 | 说明 |
|---|---|---|---|
| ① | **要本地 git 备份吗？** | **要** | 一次启用**同时解锁三样**：凭证锚（改动点附 commit hash）、越界改动检查、**强机器戳**。不启用时，人检与身份锚的戳只能到「弱」档——**能写文件的人也能写同形戳** |
| ② | **定期全盘核查几天一次？** | 7 天 | 核查是跑脚本、**不烧 token**；周期只决定「多久没人跑就要报红」 |
| ③ | **工作流之外的脚本要装哪些？** | 见下 | 它们**不进日常接手路径**，只在用户自己想检查时用 |

**工作流之外的脚本清单**（这些不在"接手三步"里，属可选装）：

| 脚本 | 用途 | 何时自己跑 |
|---|---|---|
| `audit_all.py` | 全盘核查：编排全部门禁 + 留痕 + 超期自查 | 定期 / 接手前 / 觉得哪里不对时 |
| `overview.py` | 一屏全貌：状态、计数、红黄项 | 任何时候，秒级 |
| `code_metrics.py` | 代码度量 | 每次改代码后 |
| `new_local.py` | 本项目专属检查的脚手架 | 通用门禁覆盖不到时 |
| 定时 / 可视化 / 报告 | **强依赖平台，只登记不实现**（见 `tools/`） | 按需 |

> **配置决定本身也要留痕**：`setup.py --apply` 会把「当时选了什么」写进元数据通道——
> 否则「当时选了 git」又是一条无据的声明（见 `references/audit.md` §2.0）。

## 6. 交付话术：初始化收尾必须说的话

**说明**：任务卡与设计卡是**人机之间的派发接口**——由人开口、AI 落卡。
接口没被用户知道，功能就等于没装：文件都在，却没人会派发。**没被用起来的功能不是功能，是负担。**
典型的坏结局是：工作区建得很齐，用户照旧用"你帮我改一下 XX"重新开始——卡白建了。

**三条纪律**：

1. **话术照读，不临场组织**——临场发挥会随模型的表达欲漂移，最后变成一段没人看的功能介绍。
2. **交付的证据是用户的答复，不是 AI 的声明**（锚源原则，见 `references/audit.md` §2.0）——用户答「要」才建卡；答复原文写进 `REVIEWS.md`。
3. **只交付一次**——初始化说一遍；之后靠 `MAP.md` 的「派发口令」行与 `references/cheatsheet.md` 兜底，不重复念。

**照读四句（按顺序，不要合并成一段）**：

| # | 说什么 | 目的 |
|---|---|---|
| ① | 「今后的活可以按**任务卡**派发：一件事一张卡，卡上写清要做什么、在哪做、做到哪一步。换 AI 或换对话窗时，新的 AI 只读这张卡就能接上，不用重讲背景。」 | 让用户知道卡的存在与价值 |
| ② | 「要不要现在就把手上的第一件事写成任务卡？你只要说一句『新建任务：<要做的事>』，我来落卡。」 | **把能力换成一次具体动作**——不问就没有第一次 |
| ③ | 「如果这件事**得先定方案**（改结构、定接口、选技术路线、影响面大），我先出一张**设计蓝图为**你确认方向，你点头后我再补**设计详述**、然后拆成任务卡——**未定稿的设计不生成任务卡**。用完的设计卡收进设计区自己的归档，不混进工作记录。」 | 让用户知道"要先设计"这一步、由谁发起，以及**他只看一屏蓝图** |
| ④ | 「以后常用的两句就够：『新建任务：…』『接着做 <卡名>』。」 | 给用户可复用的口令，代替功能说明 |

**落卡动作**（用户答「要」之后，AI 执行；用户不需要知道卡长什么样）：

```
python scripts/closeout.py <管理区> new-card "<任务名>"                    # 建任务卡骨架
python scripts/closeout.py <管理区> new-card "<设计卡名>" --design         # 建**两份**：详述 + 蓝图（草案态）
python scripts/closeout.py <管理区> design-archive "<设计卡名>"           # 拆完 / 作废后归档（两份一起移）
```

**兜底与防伪**：

- **用户没回答 → 记为未交付**，下次对话再问一次；**不得自行代填用户的答复**。
- **`--cards unasked` 是合法状态**：脚本会输出 `[待核]` 提醒——宁可留一个待核，不要一条假账。
- 话术是 `#人检` 条款：**读没读、问没问，机器看不见**；能机检的只有"用户的答复有没有被记录"。

```
python scripts/overview.py <管理区>
```
