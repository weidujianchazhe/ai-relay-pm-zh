
## 一、这个技能解决什么

| 问题 | 机制 |
|---|---|
| 换一个 AI 后接不上 | **任务卡驱动接手** + 指针链（卡「上次交接」→ 记录）；**索引用于全局判断，不在接手路径内** |
| 新接手者要读全部文档 | **路由表**：只读所需——**读多少由卡决定，不由文档总量决定** |
| 指令模糊、AI 走错任务 | 卡内含**涉及文件路径 + 上次交接指针**，精准到达不靠猜 |
| 交接文件啰嗦 | **最小交接 6+1 块**；不贴 diff、不复制代码 |
| 改动无法追溯 | **索引一行一条** + 指向完整记录 |
| 多 AI 同时写互相踩 | **单写者原则** + 认领 + 独立记录文件 + 冲突文件 |
| 文档越攒越大 | **快照式状态** + 分层索引（热区/冷区）+ 滚动归档 |
| 技能自身事务污染项目档案 | **元数据通道**（REVIEWS.md），项目档案只存工作记录 |
| 每个项目都要重写检查脚本 | **脚本随包分发**（`scripts/`）——不必重造轮子 |

> **名词速查**：**指针链**＝卡「上次交接」→ 记录 的引用链；**热区 / 冷区**＝索引的最近若干行 / 归档全量（移入不删除）；**元数据通道**＝技能自身留痕文件（`REVIEWS.md`）；**6+1 块**＝交接报告的最小结构（六段 ＋ 任务卡更新）。完整术语见 `references/glossary.md`。

## 一之二、它明确**不做**什么（诚实边界）

- **不拦「绕过脚本直接改文件」**——拦不住，改为**事后检测**（哈希漂移 + 冲突文件）；
- **不做实时监督**——只在提交时与定期核查时介入；
- **不做多文件事务**（无「全或无」）——半事务由 `closeout.py repair` **幂等补偿**收敛；
- **不做跨机器互斥**——前提是「一个工作区一份本地文件系统」。

## 二、快速开始（新项目）

> 首次建工作区约 **5 分钟**（脚本就位 + 填 MAP）；**存量项目**走 `LEGACY_ONBOARDING.md`。

**位置从哪来（两种启动场景）**：
- **孤立对话**（无工作区）：只有模型底座的默认存储位置 → **必须由用户指定放哪**（AI 先显示自己**当前所处位置**，再请用户确认或另指）。
- **工作区**（用户已提前建好工作区）：AI 能识别当前工作区目录（其操作范围就是它）→ **默认放在该目录下**；用户只需确认「就放这个工作区下」+ **项目名**。
- **盘位提示（判别式）**：候选若落在**系统盘**（Windows 的 `C:`）→ 追加一句「系统盘空间有限，建议放数据盘（D:/F: 等），或直接选你已有工作区所在的那块盘」；候选已在数据盘 → 不必提示。

> 创建 / 选择是**一次性动作**：做好或选好即止，后续命令直接用这两个路径，**不再重复询问**（也不写入任何持久配置）。

```
① 确认两个位置（**一次性**；**由 AI 在启动时按本清单逐项建——不是脚本自动创建**）
     项目目录（项目包本体）：**放哪** + **叫什么名**——由用户定（默认给工作区名，可改）
     管理区目录（管理区目录）：**默认与项目目录同级**，名 = `<项目名>-管理区`（不单独问用户）
     先查重：该父目录下若已有本项目的管理区 → 归并/确认唯一正本，禁止另起
② 建工作区（不整包复制；按 references/artifacts.md §1「管理区文件清单」逐项建）
     实例化：config/defaults.yml → config.yml、templates/*.template.md → 去掉 .template
     原样复制：SKILL.md、MANIFEST.md、references/（协议正文）、scripts/（脚本）、
               archives/README.md、tools/README.md
     创建空目录：tasks/ reports/ archives/done/ archives/INDEX_archived.md
③ 填 MAP：替换占位符 + 确认规则段配置
     （索引热区行数 / STATE 字数上限 / reports 归档阈值 / 定期排查开关 / 协作模式）
④ 登记第一条任务卡（tasks/，按工作命名）
⑤ 告知参与 AI：「管理区在 {MGMT_ROOT}/<项目名>/，先读 tasks/ 里对应的卡」
     项目目录**已建但为空**——代码由你放进来；本技能只管**管理区**
     **命名提示**：建议用**能认出来的名字**；**改名需重命名两个目录 + 同步 MAP**
     新管理区**没有交接记录**，`check_closeout` 会报 `[待核]`（exit 2）——**属正常**；建区只跑上一步那两个脚本
     `validate_workspace` 建区后会报 **4 条 `[建议]`**（无任务卡 / designs 为空 / 无 HANDOVER 模板 / 无人检标记）——**退出码 0，属正常**
```

**存量项目（已开工、无管理结构）**：跳过 ②~④，读 `LEGACY_ONBOARDING.md` 执行接入
（轻量登记 + 渐进整理，**不深挖历史**）。

## 三、接手一项工作（三步）

```
① 读 tasks/<卡>.md                  —— 定位工作
② 沿卡「上次交接」读 reports/<一篇>  —— 不够用时才读
③ 需要全局判断时读 STATE.md / MAP.md —— 首次接手 / 跨模块 / 整体审视
```

读完即把增量**写回**卡（保证每篇记录最多被读一次），然后开工。

> **"两份文件"说的是读哪些，不是读多少。** 成本按**字符**量：卡 + 指针记录 ≤ `{{config:capacity.onboarding_max_chars}}`、
> 单卡 ≤ `{{config:capacity.card_max_chars}}`（跑 `overview.py` 看「接手包」一行）。
> **文件数恒定 ≠ 成本恒定**——读进来的东西会留在上下文里，跟着整场对话一起付费。

## 四、提交（closeout）

提交项数**随形态**（light＝三项：记录 / 卡 / 索引；standard·coordination＝四项＋快照），缺一不算提交，**失败即阻塞**：

```
① 交接报告 ② 任务卡 ③ 索引镜像写 ④ 快照字段级更新
```

提交前跑：`python scripts/check_closeout.py <管理区>`

## 入口下沉：使用前提与边界（2026-10-02）

**使用前提**：只有两条——**本地文件系统**与**命令/文件执行能力**（能落盘目录、读写任务卡与记录）。
**平台无关**：不依赖任何平台私有接口、技能系统或 API。技能系统有则装，无则按文档读取。
**不适用**：无本地文件能力的场景（网页对话 / 移动端 / 纯对话 / API 裸调）。
**边界声明（分界线不是「实现 / 不实现」，而是「调用即执行 / 常驻自动触发」）**：
> **本包不是「AI 行为控制系统」**——它是**项目管理协议 + 检查工具**。
> 它**不拦你，它记录你**；要拦，得靠**宿主沙箱**（运行环境配置）与**唯一写入口**（见 `references/artifacts.md` §9.3）。
> 名字里有「协作管理」，但**它管理的是状态与痕迹，不是 Agent 的行为**。
- **随包提供、默认启用·调用即执行**：协议正文、模板、**可执行脚本**（结构校验 / 提交门禁 / 索引镜像写 / **归档** / 一致性对账 / 代码度量 / 机器戳）。
- **不实现、也不默认启用·常驻自动触发**：运行时守护进程、权限系统、定时或事件驱动地自动跑、把 AI 行为实时管住的持续监督。
> **"运行时守护进程"指什么**：一个常驻后台、在 AI 每次读写时**实时介入**的进程（拦截写入、强制加锁、自动回滚）。
> 不做它的两条理由：① 它需要**运行时权限与平台能力**，一旦打包就绑死平台；
> ② 它承诺的是"防呆"——而防呆一旦失效，使用者会以为"有它在就不会错"，**比没有更危险**。
> 本包换的是**事后可审计**：不拦你，但你做了什么一定会留痕。
>
> **归档器为什么可以做**：它**调用即执行、结果确定、失败可回滚**，不是常驻触发——只是把手工动作写成了脚本。
>
> **默认开的判据不止一条**：
> ① **烧不烧 token**——脚本核查不消耗模型上下文 → 开；把检查写成「读文档判断」才烧。
> ② **会不会造成假账**——开了就**必须留痕**（见 `references/audit.md` §6）：开关不是许可，是承诺，承诺由痕迹核实。
> 设计前提：文档协议**不做、也做不到实时监督** AI——监督是脚本层的职责。
> 文档层的任务是**事后可审计**：每条声明至少有两个以上独立记录互证。
> 协议不为"AI 一定守规矩"而设计，为"**不守规矩必留痕**"而设计。
