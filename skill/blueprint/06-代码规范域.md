# 第 6 页 · 代码规范域

> 这一页回答：**写代码的规矩有几本、谁在执行、范例从哪来。**

---

## 一、两本，按判据形态分家

| 文件 | 收什么 | 形态 |
|---|---|---|
| `references/code-quality.md` | 三档阈值 / 豁免机制 / 覆盖率 / 依赖方向 / 异常自愈 / 注释规范 | **有阈值、可机检**，违反即打回 |
| `references/code-style.md` | 命名 / 版面 / 抽象复用 / 重构三回合 / 范例库 / 提交信息 | **靠人读**，评审时对照 |

**级别（[强制]/[推荐]/[参考]）说的是「违反的后果」，不是「能不能机检」**——两本都会出现 [强制]。

## 二、三档语义（唯一一套数值）

| 档 | 含义 | 落点 |
|---|---|---|
| **推荐线** | 理想目标，不强制 | 静态分析平台与人工评审提示 |
| **预警区** | 允许存在，**但必须写明未拆分原因** | 不阻断；理由由定期回查判真伪 |
| **拦截线** | 只卡明显失控的代码 | 流水线以非零退出码阻断 |

**工具只配拦截线**：配两套数值必然互相矛盾；用流水线阻断「未达推荐线」会把规范变成官僚成本。
**数值唯一权威**：正文只引用键名 `{{config:code_quality.*}}`；查值顺序＝实例 MAP 规则段 → `config/defaults.yml`。

## 三、每条条款都要有执行者

四类：**脚本**（本包机检）· **平台**（CI / 静态分析 / 覆盖率）· **人检**（判断类）· **未实现**（规范债务）。
**没有执行者的条款等于没有条款**——`scripts/gen_views.py` 第 7 节核对：正文引用了却没登记执行者的键会报红。

| 已由脚本机检 | 由平台 / 人执行 |
|---|---|
| 函数行数 · 嵌套 · 圈复杂度 · 文件长度 · 注释密度 · 豁免理由真伪 · 扫描覆盖 · 依赖方向 | 覆盖率（CI 工具）· 豁免回查（人检）· 重复代码提取线（评审锚点） |

## 四、约束对象的边界

- 受约束的是**项目业务代码**（交付物本身）；
- **技能包自带的工作流 / 工具脚本不在门禁范围内**——它们的正确性由变异自检保证，不由三档阈值保证；
- 需要时仍可手工度量，那些读数是**参考**，不构成「违反本规范」。

## 五、范例库：两个分区，必须分开

| 分区 | 放什么 | 入库门槛 | 用途 |
|---|---|---|---|
| `examples/project/` | 本项目自己沉淀的范例 | **必须过流水线 + 评审** | 可当模板抄 |
| `examples/external/` | 外部参考（别处看到的好代码） | 不要求在通过状态，但**必须登记来源与许可** | **恒为「参考·未验证」**，只作参考 |

**为什么分开**：两者可信度来源不同——项目范例的可信度来自「在本项目跑过、被评审过」；
外部参考的可信度只来自「别人说它好」。混放等于把**未验证的东西**标成项目标准。

**外部参考的纪律**：登记来源与许可（`#人检`）；许可未知的按**不可复制**处理；
要当模板，唯一路径是改写进本项目 → 过流水线与评审 → 作为 `project/` 条目重新入库。

## 六、落地与机检

- 按栈落地：`adapters/` 六份（python / javascript / typescript / java / go / rust）——工具映射 + 阈值→参数 + 可复制配置样例；
- 流水线接线：`ci/`（先跑变异自检证明门禁活着，再跑核查）；
- 机检脚本：`scripts/code_metrics.py`（可单独拷进项目使用，阈值有脚本内兜底且与 config 逐键对齐）。
