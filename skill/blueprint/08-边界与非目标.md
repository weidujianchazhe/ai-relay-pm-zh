# 第 8 页 · 边界与非目标

> 这一页回答：**它不做什么、要什么前提、单独用时缺哪些门禁。**
> 写清楚边界不是谦虚——**缺门禁要让人知道，不能让人以为还有**。

---

## 一、使用前提

只有两条：**本地文件系统** + **命令 / 文件执行能力**（能落盘目录、读写任务卡与记录）。
**平台无关**：不依赖任何平台私有接口、技能系统或 API——技能系统有则装，无则按文档读取。

## 二、不适用

- 无本地文件能力的场景：网页对话 / 移动端 / 纯对话 / API 裸调；
- 单轮问答与代码片段生成（本包管的是**跨会话接续**，不是单次问答）。

## 三、包体边界（什么在包里、什么不在）

| 在包里 | 不在包里 |
|---|---|
| 协议正文（Markdown）· 骨架模板 · 可执行脚本（仅标准库）· 出厂默认值 · 按栈附录 · 接线样板 · 范例库骨架 | **HTML 展示页与任何二进制资源** · 平台专属实现 · 项目专属数据 · 沿革与事件记录 |

- **不携带 HTML 与二进制资源**：展示面是**派生**的（内容取自本蓝图），放进包里就会出现**第二份真值**——
  改了协议忘了改展示页，读者拿到的是过期版本。**展示页随发布单独给，不进包。**
- **项目专属数据不进包**：包内不得出现具体项目名、真实机器码、绝对路径（示例除外）。
- **沿革与事件留包外**：包内只写规则；"为什么变成现在这样"写在包外的史料里
  （例外：**防止有害回退**的依据要留——例如容量上限旁边的实测数字，它防止有人把上限调大）。

## 四、不做什么（设计上的非目标）

| 不做 | 为什么 |
|---|---|
| **实时监督 AI** | 文档协议做不到；监督是脚本层的职责。文档层换的是**事后可审计**：不拦你，但你做了什么一定留痕 |
| **运行时守护进程 / 权限系统** | 需要平台能力，一打包就绑死平台；且它承诺「防呆」，一旦失效比没有更危险 |
| **判语义** | 脚本只回答确定性判据；语义类一律输出 [待核] 交人或模型——**误报掩盖真实问题是门禁的首要失效原因** |
| **替人裁决** | 冲突、废弃、归档的争议由管理者裁定；脚本只给证据与状态 |
| **平台定时 / 可视化 / 报告实现** | 强依赖平台，只登记规范（`tools/`），不随包实现 |

### 4.1 架构级非目标（**评审常提，这里一次说清**）

下面几项是"把协议升级为系统强制"的典型提案。**它们都不是遗漏——看过、想过，有的做了、有的决定不做**，逐条写清：

> **已经做了的那部分**：**任务级租约**（`claim / release`）· **共享文件 CAS** · **同一文件系统内的锁**（`O_EXCL`）· **半事务补偿**（`closeout.py repair`），
> 见 `references/concurrency.md` §0「两级强制 + 一级检测」——
> 它强制的是**经由脚本的写入**，而**绕过脚本的直接编辑由检测层抓**（卡上记的哈希对不上 → 报问题 + 生成冲突文件）。
> **这就是本包能做的那一半；剩下那一半（拦不住直接编辑）不是不做，是做不到——所以改成"一定看得见"。**

| 常见提案 | 与什么冲突 | 为什么不做 |
|---|---|---|
| **Workspace API**（Agent 不得直接改管理文件，必须走受控接口） | 「调用即执行 / 不常驻」分界线 | 需要常驻服务或平台运行时拦截；本包只在**写入时**提供脚本与门禁，不做"必经的关口" |
| **Policy / Permission Layer**（按 who/what/where 强制拦截） | 同上 | 需要运行时权限系统；且**防呆一旦失效比没有更危险**（使用者以为"有它在就不会错"） |
| **跨机 / 分布式锁**（把互斥扩展到多台机器） | 并发篇 §7 的诚实边界 | 跨平台锁语义不可靠（网络盘、容器、不同 OS）——**做一半的锁比没有锁更危险**。**同一文件系统内的短临界区互斥已做**（`O_CREAT|O_EXCL` 锁文件，见 `concurrency-internals.md` §2） |
| **Event Sourcing**（STATE 由事件投影生成） | 「写路径恒定」（change-control §A 第 4 条） | 状态由事件投影＝每次提交都要重放/全量盘点，**把成本推向高频路径**；本包的口径是"累计统计归总账按需查询" |
| **Agent 身份认证** | 锚源原则的边界 | 机器戳与运行证据都是 **runtime evidence**，不是身份认证——本包**从不说它们是认证**。身份模型分四种（运行时 / 机器 / 模型 / 人），**只有前两种可用，模型多半拿不到、人不采集**，见 `references/audit.md` §2.2 |
| **Agent 间通信**（REQUEST_REVIEW / REPORT_BLOCKER 等消息协议） | 「不常驻、不拦截」 | 需要**投递与唤醒**（常驻或平台推送）才能算通信；本包现在做的是**共享文件 + 租约**——消息要落地成文件，就得有人轮询，而轮询＝常驻。**可以做的替代**：把消息写成任务卡（结构化、可审计、有归属），让"发现"由人/脚本的**定期扫视**承担 |
| **统一 Tool Gateway + Task/State/Audit API** | 「不常驻 + 不绑平台」 | 那是**运行时产品**的形态：需要有东西在 Agent 与文件系统之间站着。本包是**协议 + 脚本**，站在流程里而不是站在调用路径上；要做等于换定位（见 §4.2） |
| **多 Agent 调度 / Capability Registry / 分布式 Workspace** | 同上 | 需要中央调度器与全局视图，与「每项目可配、无中心」冲突 |

### 4.2 要转成"强制型"意味着什么

那是一次**定位变更**，不是优化：需要运行时（守护进程或平台 API）、需要承担"防呆失效"的责任、
并且**必然绑死平台**。本包选的是另一条路——**事后可审计**：

> 不拦你，但你做了什么一定留痕；**谁的声明，就在哪里留下不是自己写的证据。**

### 4.3 已经做了、但评审容易漏看的（常见问题对照）

| 常见提案 | 包内已有的对应机制 |
|---|---|
| 可配置质量门禁（recommendation / warning / blocking） | `references/code-quality.md` §1 三档语义 + **实例 MAP 规则段覆写**（真值顺序：实例 → 出厂默认） |
| 轻量模式 / 按复杂度逐级启用 | 四种形态 `card / light / standard / coordination` + `MANIFEST.md` 的「子能力与最小集」 |
| 自动化 Closeout（一条命令跑完全部门禁） | `scripts/closeout.py` 做机械步骤 · `scripts/audit_all.py` 编排全部门禁并留痕 · `scripts/check_closeout.py` 是提交门禁 |
| 自动生成 Handoff | `closeout.py new-record` 生成 6+1 骨架并自增交接号；**内容仍由人写**（语义部分不自动编造） |
| 跨语言代码质量 | `ci/github-actions-multilang.yml` 接线样板：**各栈用成熟工具**（ESLint / Checkstyle / JaCoCo），本包只统一退出码约定——**不自研度量**（行/缩进启发式误报会掩盖真问题） |

## 五、单独使用时的门禁缺口（诚实声明）

| 子能力 | 单独使用时缺什么 |
|---|---|
| **只有 MAP** | 无快照一致性校验（没有 STATE / 记录 / 索引可对账） |
| **单文件任务卡** | 全部门禁都不跑（无索引、无快照、无归档）——**一个文件就是全部**，靠人读卡 |
| **只拷 `code_metrics.py`** | 读不到实例 MAP 的阈值，用脚本内兜底值（与 `config/defaults.yml` 逐键一致） |
| **设计卡单独用** | 无定稿门禁强制（协作模式开关关闭时，设计卡可当方案笔记用） |

## 六、四档形态的边界（standard / coordination 合并一行）（升级即扩集，历史不回写）

| 形态 | 有什么 | 没有什么 |
|---|---|---|
| **卡片模式** | 一个卡片文件 | 索引 / 快照 / 记录 / 脚本 / 门禁 |
| **light 轻量工作区** | 任务卡 + 交接记录 + 索引（含冷区）+ 设计区（按需） | MAP / STATE / REVIEWS |
| **standard / coordination** | 上面全部 + MAP / STATE / REVIEWS | — |

**从严到宽，不从宽到严**：先按能跑的最小形态起步，发现不够再升。
反过来先建全套再降级，只会留下一套无人维护的空档案——**空档案比没有档案更坏，它制造「已管理」的错觉**。

## 七、脚本的适用边界

- 门禁脚本**只读不写**（`overview` / `validate_workspace` / `check_closeout` / `check_index` / `reconcile` / `code_metrics`），
  可多进程、多 AI 同时跑；
- 写工作区的脚本（`closeout.py` 各子命令）**不可并发**：同一工作区同一时刻只允许一个写者；
- 崩溃退出码为 3，与「有 [问题]」分开——**别把脚本崩了读成项目有问题**。
