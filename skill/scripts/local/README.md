# 项目自定义脚本（`scripts/local/`）

> **本目录是项目自己的**，与技能包的 `scripts/` 分工明确。
> 技能包升级**不会**覆盖本目录——但**也绝不允许**把包内脚本改成项目专用（见下「红线」）。

---

## 1. 什么放这里

**技能包装不下的、只对这一个项目成立的检查。**

| 放这里 | 放包内 `scripts/` |
|---|---|
| 只对本项目有意义的判据（如"本项目的配置键必须在 X 与 Y 两处一致"） | 通用门槛（结构 / 索引 / 提交 / 度量 / 戳） |
| 强依赖本项目工具链或目录布局的检查 | 与平台、技术栈无关的确定性函数 |
| 一次性的迁移/修复辅助（用完可留档） | 所有项目都该跑的 |

**判断问句**：这个检查换一个项目还成立吗？成立 → 它该进技能包（提 issue 回流）；不成立 → 放这里。

---

## 2. 红线（三条）

1. **不改包内脚本**。`scripts/*.py` 由技能包维护；改它会在下次升级时丢失。
   要改行为 → 提回流，或在 `local/` 里写一个覆盖检查。
2. **`local/` 的产物不进技能包**。项目专属逻辑混进通用包，是包腐化的起点。
3. **不绕门禁**。`local/` 里不得出现"把包内门禁判红的结果改绿"的逻辑——
   门禁红了就改代码，不改门禁（见 `references/cheatsheet.md`「绝不五条」）。
   同理，也不得绕过 `closeout.py` 去手改 INDEX——那会把镜像写与溢出移行的契约绕掉。

---

## 3. 接口契约（与包内脚本一致，便于统一编排）

```
输出三态    [通过] / [问题] / [待核] / [建议]（提示，不计数）
退出码      0 = 全通过 · 1 = 有[问题] · 2 = 仅[待核] · 3 = 脚本自身错误
取值顺序    实例 MAP 规则段 → 缺失才回落 config/defaults.yml
依赖        仅 Python 3 标准库（与包内一致，免装环境）
```

**复用共用设施**，不要重写样板：

```python
import sys
from pathlib import Path
sys.path.insert(0, str(Path(__file__).resolve().parent.parent))   # scripts/
from _common import ok, problem, tbd, note, read, run, summary          # noqa: E402
```

---

## 4. 脚本头部必须写的三件事

| # | 项 | 为什么 |
|---|---|---|
| 1 | **用途与何时跑** | 接手者判断"要不要跑它"的唯一依据 |
| 2 | **回本口径** | 说明它取代了什么重复劳动。**没有回本口径的门禁会被当成负担，然后被绕过** |
| 3 | **踩坑记录** | 改它之前必须知道的事。协议正文有"为什么这么做"，脚本也该有 |

---

## 5. 起手用脚手架，不要手写样板

```
python scripts/new_local.py <管理区> <脚本名> --purpose "<一句话用途>"
```

生成 `scripts/local/<脚本名>.py`：统一三态、退出码、参数解析、统计汇总**都已就位**，
只留一处 `TODO` 给你写真正的判据。

> **为什么给脚手架**：样板（三态 / 退出码 / 参数）与判据无关，手写只会写歪。
> 让机器生成样板、人只写判断——这也是本包对"临时造脚本"这件事的最终态度：
> **通用检查随包给实现；项目专属检查给脚手架，不给规格。**
